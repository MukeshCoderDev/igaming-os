# DEC-0157: Jurisdiction Removal — Global Mode

## Decision
Remove ALL jurisdiction-specific logic from Noventra OS.
The system operates in global mode — one ruleset for all players.
No JurisdictionPort, no per-jurisdiction rules, no jurisdiction fields.

## What's Removed
- JurisdictionPort interface + all adapters (stub and real)
- JurisdictionPolicy model + rules table
- jurisdiction_code field from ALL models
- Per-jurisdiction fee schedules
- Per-jurisdiction TM thresholds
- Per-jurisdiction GGR/NGR breakdown
- Per-jurisdiction contract scope
- Per-jurisdiction KYC rules
- Per-jurisdiction RG rules (SE periods, limits, reality checks)
- Per-jurisdiction DSAR windows
- Per-jurisdiction reporting formats
- Per-jurisdiction vendor acceptance rules
- Per-jurisdiction RAG query filter
- Per-jurisdiction segment filter
- Jurisdiction from RLS policies (keep tenant_id only)
- Jurisdiction from API endpoints

## What's Preserved
- tenant_id-based isolation (RLS — Law 1, Law 2)
- All 24 Laws (none require jurisdiction — they require tenant_id)
- All other architecture (ledger, audit chain, outbox, kill switch, etc.)

## Global Defaults Used
- CTR threshold: $10,000 (1,000,000 minor units)
- SE periods: 6m, 1y, 2y, 5y, lifetime
- Reality check interval: 30 minutes
- Session timeout: 4 hours
- DSAR window: 30 days
- Retention: 7 years
- Re-KYC period: 12 months
- Rev-share rate: 15% (configurable per contract, not per jurisdiction)

## Rationale
Jurisdiction complexity was blocking implementation progress.
System will operate globally with single defaults.
Per-jurisdiction logic can be re-added in future if needed.

## Future Re-addition (if ever needed)
1. Add jurisdiction_code field back to models
2. Create JurisdictionPolicy table with per-jurisdiction rules
3. Add jurisdiction filter to RAG queries and segments
4. Add per-jurisdiction fee schedules
5. Add per-jurisdiction TM thresholds
6. Add per-jurisdiction reporting formats
