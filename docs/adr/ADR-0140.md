# ADR-0140 — MarketingGate Enforcement at Scale — Queue-Time + Send-Time Two-Stage Check

## Context

MarketingGate was built in Phase 8 (ADR-0046), extended in Phase 9 (consent check), and integrated with RGPort in Phase 13/14. Phase 22 is the first phase that uses MarketingGate at scale for campaigns. The Suppression Drift pain (blueprint §3) is the canonical failure: "Purged user gets email because flag was cached."

The 2021 Bet365 enforcement (£1M) illustrated the race condition: a player self-excluded at 14:00; a campaign send was queued at 13:55 (before self-exclusion); the send fired at 14:05 (after self-exclusion). The operator's single-stage check (queue-time only) did not catch the self-exclusion because it happened between queue and send. The fix is a two-stage check: queue-time (player eligibility) + send-time (caps + consent) with a deterministic join that catches real-time changes.

The deterministic join (Law 24) is the architectural mitigation. Suppression is NEVER a cached flag; it is a live join against `suppression_list` + `frequency_cap` tables at send time. If a player self-excludes between queue and send, the send-time join catches it and the send is denied. This is the cure for the Suppression Drift pain.

## Decision

### Two-stage MarketingGate check

#### Stage 1 — Queue-Time Check (Player Eligibility)

Before a send enters the queue, MarketingGate checks:
1. **Suppression list** (Phase 8): player in `suppression_list` (unsubscribes, hard bounces, complaints)?
2. **RGPort.check_self_excluded** (Phase 14 real adapter): player actively self-excluded?
3. **RGPort.check_cooling_off** (Phase 14 real adapter): player in active cooling-off?

If ANY check fails → send NOT queued; enrollment `status=suppressed`; `exit_reason` recorded; audit event.
**Linter rule 197:** every journey step send goes through queue-time MarketingGate check.

#### Stage 2 — Send-Time Check (Per-Message Limits)

At the moment of adapter call (send), MarketingGate checks:
1. **Frequency caps** (Phase 8): tenant monthly, tenant daily, recipient daily, channel, jurisdiction (if Q1 unblocked).
2. **Consent** (Phase 9): player consented to this (purpose, channel) tuple?

If ANY check fails → send denied; audit event; step may retry (configurable; OQ-ENG-003) or advance.
**Linter rule 198:** every send goes through send-time MarketingGate check.

### Deterministic join (Law 24)

- Suppression is checked via **deterministic join** against `suppression_list` + `frequency_cap` tables at send time.
- **NEVER a cached flag** (which survives DSAR purge — the Suppression Drift pain).
- The join is live: if player self-excludes between queue-time and send-time, the send is denied (real-time protection).
- **Linter rule 200:** SegmentMembership does not include suppression flag (no cached suppression; Law 24).

### Audit

Every MarketingGate decision generates audit event (Phase 7): `marketing.gate_decision` with:
- `decision` (allow, deny)
- `reason` (suppressed, excluded, cooling_off, cap_exceeded, no_consent)
- `player_uuid`, `journey_uuid`, `enrollment_uuid`, `step_number`
- `correlation_id` (Phase 4)
- `timestamp`

**Linter rule 201:** every MarketingGate decision generates audit event.

### MarketingGate reuse

MarketingGate is the SINGLE place sends are gated (Phase 8 ADR-0046). Phase 22 does NOT create a parallel gate; it uses the existing one at scale.
**Linter rule 199:** no direct send without MarketingGate (extends Phase 8 rule 51).

### Why two stages (not one)

- **Queue-time only (single-stage)** fails the race condition: player self-excludes after queue but before send → send fires before kill-switch fan-out reaches the queue (the 2021 Bet365 incident).
- **Send-time only (single-stage)** is expensive (every queued send re-checks eligibility) and allows excluded players' sends to enter the queue (wasted queue capacity + harder to audit "was this player excluded when the send was queued?").
- **Two-stage** catches both: queue-time filters obviously-ineligible players (suppressed, excluded, cooling-off); send-time catches real-time changes (self-exclusion between queue and send) + per-message limits (caps, consent).

## Alternatives

- **Single-stage check (send-time only)** (rejected). Excluded players' sends enter queue; wasted capacity; harder audit trail.
- **Single-stage check (queue-time only)** (rejected). Race condition; player self-excludes after queue but before send → send fires (the 2021 Bet365 incident).
- **Cached suppression** (rejected). Suppression Drift pain; survives DSAR purge; purged user gets email.
- **Parallel gate** (rejected). Phase 8 ADR-0046 is the single gate; no parallel implementation; linter rule 199.
- **No audit** (rejected). Law 9; regulator inquiry cannot reconstruct "why was this send denied?"
- **Send-time check without queue-time** (rejected). Excluded players flood the queue; send-time denial for every send is wasteful.

## Consequences

- Two-stage MarketingGate check (queue-time + send-time).
- Deterministic join (no cached suppression; Law 24).
- MarketingGate reused at scale (no parallel gate).
- Every decision audited (Phase 7; linter rule 201).
- Linter rules 197, 198, 199, 200, 201.
- The 2021 Bet365 race condition is cured by the two-stage check.
- The Suppression Drift pain is cured by the deterministic join.

## Validation Plan

- **Queue-time check test (suppressed):** suppressed player; trigger journey step; assert send NOT queued; assert enrollment `status=suppressed`; `exit_reason` recorded.
- **Queue-time check test (excluded):** self-excluded player; assert send NOT queued; `exit_reason=self_excluded`.
- **Queue-time check test (cooling-off):** cooling-off player; assert send NOT queued; `exit_reason=cooling_off`.
- **Send-time check test (caps):** recipient daily cap exceeded; assert send denied at send-time; `reason=cap_exceeded`.
- **Send-time check test (consent):** no consent for (purpose, channel); assert send denied; `reason=no_consent`.
- **Deterministic join test (self-exclude between queue and send):** send queued; player self-excludes; send fires → send-time check → denied (deterministic join catches real-time self-exclusion).
- **No-cached-suppression test (linter rule 200):** grep SegmentMembership schema; assert no suppression flag columns.
- **MarketingGate reuse test (linter rule 199):** grep for send code; assert all go through MarketingGate; no direct adapter calls.
- **Audit test (linter rule 201):** trigger MarketingGate decision; assert `marketing.gate_decision` audit event with decision + reason + player_uuid + correlation_id.
