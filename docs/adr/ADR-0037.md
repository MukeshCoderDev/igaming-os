# ADR-0037 — Redaction policy + Merkle-style payload hashing

## Context

Audit events contain PII (actor identity, target identity, payload details). Per GDPR + the PII register (data-classification.md), PII must be redactable. But redaction must not break the hash chain (ADR-0035). Standard hash chaining hashes the full payload; redacting a field would change the hash and break the chain. Merkle-style hashing solves this: each field is hashed individually, and only the redacted field's hash is preserved (the value is replaced with [REDACTED]).

## Decision

Adopt Merkle-style payload hashing. Each payload field is hashed: field_hash = SHA256(field_name || field_value). The Merkle root = SHA256(concatenation of all field_hashes in canonical order). The chain hash (ADR-0035) uses the Merkle root. Redaction: replace the field VALUE with [REDACTED] but PRESERVE the field_hash. Verification: recompute field_hash from the (now redacted) value — it won't match, but the preserved field_hash proves the original value was consistent at insert time. Field-class-to-rule mapping from the PII register (data-classification.md). Irreversibility: SHA-256 is one-way. Redaction itself is audited via audit.redaction_applied event.

## Alternatives

Alternatives: (a) no redaction (full payload retained) — GDPR violation; (b) redaction breaks chain — defeats tamper-evidence; (c) encrypt-then-redact (reversible) — key management burden + reversible redaction is not true redaction; (d) separate redacted copy — storage cost + sync. (a) rejected for GDPR; (b) rejected for tamper-evidence; (c) rejected for reversibility; (d) rejected for sync.

## Consequences

Merkle-style hashing adds CPU cost per insert (~10% vs bare hashing). Field-level hashes increase storage (~2x payload size). Redaction policy must be maintained as new event types are added. Irreversibility means redacted data is gone forever (no legal hold recovery — mitigated by retention policy: redact after retention period, not before).

## Validation Plan

Phase 7: redaction preserves chain integrity test (redact a field → verifier still passes). Phase 7: every PII class has a rule (linter rule 41). Phase 7: redaction itself audited (audit.redaction_applied event). Phase 8: scheduled redaction job for aged events.
