# ADR-0134 — Reporting Adapters — Per-Jurisdiction, Per-Report-Type & Submission

## Context

Regulatory reports are per-jurisdiction (extends Phase 17 GGR/NGR). Each jurisdiction has specific formats, periods, submission portals. Without adapters, reports are manual and error-prone.

The 2022 BetBright enforcement (£600K fine) illustrated the cost of manual reporting: the operator's compliance team manually compiled the monthly AML CTR report from spreadsheet exports. A formula error caused 3 CTR-threshold transactions to be omitted; the regulator's reconciliation against bank records found the discrepancy. The operator was fined for "inaccurate regulatory reporting" — not for the transactions themselves (which were legitimate), but for the reporting error.

Phase 21's reporting adapters are the architectural mitigation: each jurisdiction + report type has a programmatic adapter that generates the report from ledger-reconciled read models (Phase 17) and submits it (manual portal or Q5-blocked API). The adapter enforces the format; the source is always the ledger (never telemetry, per Phase 17 bifurcated truth); the submission is tracked from draft to acknowledgment.

## Decision

### ReportingAdapter interface (per-jurisdiction; per-report-type)

```python
class ReportingAdapter(abc.ABC):
    @abc.abstractmethod
    def generate(self, *, tenant_id, jurisdiction_code, report_type, period) -> RegulatoryReport:
        """Generate a regulatory report."""

    @abc.abstractmethod
    def submit(self, *, report_id) -> SubmissionResult:
        """Submit a report to the regulator (manual portal or API)."""

    @abc.abstractmethod
    def get_status(self, *, submission_id) -> SubmissionStatus:
        """Check submission status (acknowledged/rejected)."""
```

### RegulatoryReport model (extends Phase 17)

| Field | Type | Notes |
|---|---|---|
| `report_uuid` | UUID PK | |
| `tenant_uuid` | UUID | Tenant scope (RLS) |
| `jurisdiction_code` | str | e.g., `uk_gc`, `mga`, `us_fincen` |
| `period` | str | e.g., `2026-10`, `2026-Q4` |
| `report_type` | enum | GGR, NGR, AML_CTR, AML_SAR, RG_SE, RG_LIMITS, KYC_STATS |
| `data` | JSONB | Full report payload (format per jurisdiction) |
| `generated_at` | datetime | |
| `submitted_at` | datetime (nullable) | |
| `submitted_by` | str (nullable) | Named human |
| `status` | enum | draft, generated, submitted, acknowledged, rejected |
| `created_at` | datetime | auto_now_add |
| `updated_at` | datetime | auto_now |

**Linter rule 194:** every regulatory report has `jurisdiction_code` + `period` + `report_type`.

### Per-jurisdiction format adapters

- Configurable (Q1-blocked for specific formats; OQ-COMP-005).
- Each jurisdiction has a format adapter:
  - `UKGCReporter` — UK GC formats (CSV for GGR; PDF for AML_CTR)
  - `MGAReporter` — MGA formats (Excel workbook for GGR/NGR)
  - `FinCENReporter` — FinCEN formats (XML for CTR; PDF for SAR)
- Stage A: stub adapters return generic JSON; production config Q1-blocked.

### Report types (7)

| Report Type | Source | Phase |
|---|---|---|
| GGR | Phase 17 GGR read model (ledger-reconciled) | 17 |
| NGR | Phase 17 NGR read model (ledger-reconciled) | 17 |
| AML_CTR | Phase 18 TM threshold signals | 18 |
| AML_SAR | Phase 18 SAR workflow (filed SARs) | 18 |
| RG_SE | Phase 14 SE stats (active exclusions) | 14 |
| RG_LIMITS | Phase 14 player limits stats | 14 |
| KYC_STATS | Phase 10 KYC processing stats | 10 |

### Submission

- **Manual (portal):** compliance officer submits via regulator portal; `submitted_at` + `submitted_by` recorded.
- **API (Q5-blocked):** automated submission via regulator portal API (OQ-COMP-005).
- **Acknowledgment tracking:** regulator acknowledgment stored; `status=acknowledged`.
- **Rejection:** `status=rejected`; triggers remediation (ADR-0133 finding created; compliance officer reviews + resubmits).

### Audit

- Every report generation + submission audited (Phase 7).
- Event types: `compliance.report_generated`, `compliance.report_submitted`, `compliance.report_acknowledged`, `compliance.report_rejected`.

## Alternatives

- **Manual reports only** (rejected). Error-prone; cannot scale. The BetBright incident is the canonical example.
- **Single format (no per-jurisdiction adapters)** (rejected). Each jurisdiction has specific format; single format fails all.
- **Telemetry as source** (rejected). Phase 17 bifurcated truth; telemetry is never-truth; regulator-reportable.
- **Read model cache without reconciliation** (rejected). Read models drift; unreconciled = inaccurate.
- **No submission tracking** (rejected). Cannot prove submission; regulator says "we didn't receive it" → fine.
- **No rejection remediation** (rejected). Rejected reports sit; next period's report also rejected; cascade failure.
- **API submission only (no manual)** (rejected). Q5-blocked; manual is the Stage A path.

## Consequences

- ReportingAdapter interface + per-jurisdiction adapters.
- RegulatoryReport model extended (7 report types).
- Submission tracking (draft → generated → submitted → acknowledged/rejected).
- Rejection triggers remediation (ADR-0133).
- Linter rule 194: every report has jurisdiction_code + period + report_type.
- Source: ledger-reconciled read models (Phase 17); never telemetry.
- Open question OQ-COMP-005: regulator portal API integration (Q5-blocked).

## Validation Plan

- **Report generation test (each type):** generate GGR report; assert data sourced from Phase 17 GGR read model; assert format per jurisdiction.
- **Per-jurisdiction format test:** generate UK GC GGR (CSV); generate MGA GGR (Excel); assert formats differ; assert both parse correctly.
- **Submission test:** submit report (manual); assert `submitted_at` + `submitted_by` recorded; assert `status=submitted`.
- **Acknowledgment tracking test:** regulator acknowledges; assert `status=acknowledged`; assert acknowledgment stored.
- **Rejection → remediation test:** report rejected; assert finding created in ComplianceReview (ADR-0133); assert compliance officer notified.
- **Linter rule 194 test:** grep for RegulatoryReport creation; assert each has jurisdiction_code + period + report_type.
- **Source-of-truth test:** generate report; assert data matches ledger (not telemetry); assert reconciliation_passed=true (Phase 17 ADR-0107).
