# ADR-0095 — Deterministic Sandbox — Same Code Path + Seeded RNG

## Context

Sandbox environments must produce identical outcomes for identical inputs (deposit, bet, settle) so that operators can rehearse operational procedures and labs can reproduce certification evidence. Without determinism, every sandbox run differs, certification cannot be replayed, and operator training produces false confidence. The sandbox must not be a separate code path — that creates drift where sandbox passes but production fails. The sandbox must run the same domain code as production with only the I/O adapters swapped (real PSP → sandbox PSP, real RNG → seeded RNG).

## Decision

The sandbox runs the **same domain code path** as production. The only differences are:
- A `DeterministicRngAdapter` is injected in place of `ProductionRngAdapter`. The adapter is seeded with a fixed seed per session; the seed is logged on round initiation, so every round outcome can be reproduced exactly.
- A `SandboxPspAdapter` is injected in place of the real PSP. Authorize, capture, refund return deterministic success; webhook verification accepts any signature (the sandbox cannot receive real webhooks).
- The clock is injected via a `ClockPort`. Production uses `datetime.now(timezone.utc)`; sandbox uses a `FakeClock` that advances only on explicit `tick()` calls.
- All other code (FSM transitions, ledger posting, audit events, outbox emission) is byte-identical between sandbox and production.

The sandbox seed is recorded on the round at initiation (`rng_seed_hex`) and is part of the round hash (Phase 16 ADR-0101). This means a round played in sandbox can be re-played against the production code path with the same seed and produce the same outcome — the test of the deterministic sandbox property.

## Alternatives

- **Separate sandbox code path** (rejected). Diverges from production; sandbox passes do not predict production behavior. Maintenance doubles.
- **No determinism** (rejected). Cannot reproduce certification evidence; cannot train operators on known scenarios; cannot regression-test math changes.
- **Mock everything** (rejected). Mocks at the test layer, not the runtime layer, so operators do not get a runnable sandbox.

## Consequences

- A new `DeterministicRngAdapter` and `ClockPort` abstraction are required (Phase 16 implements the real adapters).
- The sandbox must be enabled only when `ENV=sandbox`. Production deployments must refuse to boot if `ENV=sandbox` is set (defensive: prevents accidental sandbox in prod).
- Round reproduction becomes a first-class operation: given (math_version, rng_seed, bet_config), the outcome is reproducible. This is also the basis for the certification evidence generator (Phase 16 ADR-0102).

## Validation Plan

- Determinism test: same seed + same input → identical outcome across 100 runs.
- Code-path equivalence test: diff the call graph of sandbox vs production for a deposit→bet→settle flow; assert only adapter calls differ.
- Boot refusal test: `ENV=sandbox` in production settings raises on startup.
- Seed-replay test: capture (math_version, rng_seed, bet_config) from a sandbox round; replay against production code path; assert identical outcome hash.
