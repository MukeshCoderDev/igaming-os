# ADR-0005 — SAML for enterprise tenancy SSO

## Context

Enterprise tenants often mandate SAML 2.0 for SSO due to existing IdP investments (Azure AD, Okta, Ping). Supporting only OIDC excludes this segment. DEC-0004 covers default tenants; this decision covers the enterprise tier.

## Decision

Support SAML 2.0 as a second-tier federation protocol for enterprise tenants. SAML assertions are exchanged for the platform's internal auth tokens at the identity service boundary; downstream code is unaware of the original protocol.

## Alternatives

Alternatives considered: (a) OIDC-only with brokered SAML — requires a broker (e.g., Keycloak) in front of enterprise IdPs, adding a SPOF; (b) SAML-only — excludes modern clients; (c) SCIM-only — SCIM is provisioning, not SSO. (a) rejected for SPOF; (b) rejected for client coverage; (c) rejected for scope mismatch.

## Consequences

SAML XML signatures are a frequent source of vulnerabilities (XML signature wrapping). Metadata exchange is operationally heavy. Just-in-time provisioning may conflict with enterprise offboarding procedures.

## Validation Plan

Phase 5: integrate with one enterprise IdP (Azure AD) end-to-end including metadata exchange and signed assertions. Phase 5 penetration test: XML signature wrapping, certificate substitution, audience restriction bypass.
