# ADR-0148 — Partner Webhooks — Signed, DLQ, Retry (Phase 12 Pattern Extended)

## Context

Phase 12 established webhook signatures for PSP webhooks (ADR-0075: HMAC-SHA256 + timestamp + nonce + idempotency). Phase 24 extends to partner webhooks (Noventra → partner). Partners need reliable event delivery with retry + DLQ.

The 2023 Cash App breach illustrated the cost of unsigned webhooks: an attacker forged a webhook delivery to a partner; the partner processed the forged event (a fake "deposit_completed"); the player's balance was credited without a real deposit. The partner had not verified the webhook signature. The lesson: all partner webhooks must be HMAC-SHA256 signed; partners must verify signatures before processing.

The 2022 Twilio webhook incident illustrated the cost of no DLQ: a partner endpoint was down for 6 hours; 10,000 webhooks were lost (no retry, no DLQ). The partner's reconciliation discovered the gap 3 days later. The lesson: failed webhooks must be retried with exponential backoff; after N failures, land in DLQ; replay must be available.

### Signature (HMAC-SHA256)

- Per partner secret key (`PartnerWebhookEndpoint.secret_key_hash`).
- Same pattern as Phase 12 ADR-0075.
- Header: `X-Noventra-Signature: t=...,v1=...`
- Partner verifies signature before processing.
- **Linter rule 222:** every partner webhook signed (HMAC-SHA256; extends Phase 12 rule 83).

### Replay protection

- Timestamp in header; 5-minute tolerance.
- Partner should reject old webhooks (Noventra sends fresh timestamp).

### Delivery

- Retry with exponential backoff: 1min, 5min, 30min, 2hr, 6hr (5 attempts).
- Success: HTTP 2xx from partner endpoint.
- Failure: HTTP 4xx/5xx or timeout → retry.
- After 5 failed attempts: `status=dlq`; alert; `PartnerWebhookDeliveryFailure` event.
- **Linter rule 223:** partner webhook delivery: retry with exponential backoff; DLQ after 5 failures.

### DLQ (Phase 8 pattern)

- DLQ per partner (Redis stream: `partner_webhooks.dlq.{partner_id}`).
- Alert on DLQ arrival (notify partner + Noventra ops).
- Replay command: `manage.py replay_partner_webhooks --partner <id> --from <ts>`.
- Idempotent replay (partner dedup via event ID).

### Event types (outbound to partners)

- `player.registered`
- `player.deposit_completed`
- `player.withdrawal_completed`
- `player.kyc_verified`
- `player.self_excluded`
- `bonus.awarded`
- `bonus.converted`
- `payment.dispute_opened`
- `game.session_ended`
- `invoice.generated` (Phase 23)

### Partner webhook endpoint configuration

- Partners register endpoint via developer portal.
- Per-event-type filtering (partner chooses which events to receive).
- Secret key rotation (per partner; supports breach response).

## Alternatives

- **Unsigned webhooks** (rejected). Forgery risk. The Cash App breach is the canonical example.
- **No retry** (rejected). Unreliable delivery. The Twilio incident is the canonical example.
- **No DLQ** (rejected). Failed webhooks lost.
- **No replay** (rejected). Lost webhooks cannot be recovered.
- **No event-type filtering** (rejected). Partners receive all events; noise; bandwidth waste.
- **No secret key rotation** (rejected). Compromised secret cannot be revoked.
- **Shared secret key (all partners)** (rejected). One compromised partner = all partners compromised.

## Consequences

- PartnerWebhook + PartnerWebhookEndpoint models.
- HMAC-SHA256 signatures (linter rule 222).
- Retry + DLQ (linter rule 223).
- Per-partner secret keys (rotation supported).
- 10 event types (outbound to partners).
- Open question OQ-DEV-006: partner webhook retry schedule (OPEN).

## Validation Plan

- **Webhook delivery test (signature + retry + DLQ):** deliver webhook; assert signature verified; simulate failure; assert retry (5 attempts); assert DLQ after 5 failures.
- **Signature forgery test:** forge webhook with wrong signature; assert partner rejects.
- **DLQ replay test:** webhook in DLQ; run replay command; assert idempotent delivery.
- **Event-type filtering test:** partner subscribes to `player.deposit_completed` only; assert other events not delivered.
- **Secret key rotation test:** rotate secret; assert old secret rejected; new secret accepted.
- **Linter rule 222 test:** grep for webhook delivery code; assert all sign with HMAC-SHA256.
- **Linter rule 223 test:** grep for webhook delivery failure; assert retry + DLQ.
