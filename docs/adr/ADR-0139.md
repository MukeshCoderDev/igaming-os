# ADR-0139 — Propensity Features, Feature Store & ML Model Governance (EU AI Act)

## Context

Propensity features (churn risk, LTV, deposit propensity, bonus sensitivity, RG risk) are derived player attributes used for segmentation. These are ML outputs — the EU AI Act applies (Phase 19 model inventory, ADR-0123). Risk classification: limited (transparency obligations — player must know their features are used for marketing).

The 2024 EU AI Act enforcement guidance clarified that propensity scoring for marketing falls under "limited risk" (Annex III candidate; transparency obligations apply). The player must be informed that their behavioral data is used to compute propensity features for marketing targeting. Failure to disclose is a fineable offence (up to €15M or 3% of turnover).

The Q21 open question (EU AI Act classification of retention AI; Phase 19 OQ-AI-003) is related but distinct: Q21 covers the retention AI (Phase 9) which makes automated decisions; propensity features are inputs to segmentation, not automated decisions. Propensity features are "limited risk"; retention AI may be "high risk" (Q21 OPEN). Phase 22 treats propensity models as "limited risk" by default; Legal Counsel may upgrade to "high risk" per Q21 resolution.

## Decision

### PropensityFeature model

| Field | Type | Notes |
|---|---|---|
| `feature_uuid` | UUID PK | |
| `tenant_uuid` | UUID | Tenant scope (RLS) |
| `player_uuid` | UUID | |
| `feature_name` | enum | churn_risk, ltv, deposit_propensity, bonus_sensitivity, rg_risk |
| `feature_value` | float | |
| `computed_at` | datetime | |
| `model_version` | str | e.g., `churn_risk_v2_2026-10-01` |
| `created_at` | datetime | auto_now_add |

**Unique constraint:** `(tenant_uuid, player_uuid, feature_name, model_version)` — no duplicate features per player per model version.
**Insert-only** (per model_version): corrections require a new model_version; old features retained for audit.

### Feature engineering

- **Scheduled job (nightly):** Celery task at 03:00 UTC; computes features for all active players.
- **Sources:**
  - Phase 17 GGR/NGR read models (revenue, activity).
  - Phase 11 ledger (transaction history).
  - Phase 14 RG records (limits, SE history, distress signals).
  - Phase 18 risk signals (AML, fraud indicators).
- **Feature store:** materialized `propensity_feature` table; per-player; per-feature; versioned by `model_version`.

### Feature catalog (closed enumeration — 5 features)

| Feature | Description | Source | Range |
|---|---|---|---|
| `churn_risk` | Probability of player churning | Phase 17 activity + Phase 11 ledger | 0.0-1.0 |
| `ltv` | Lifetime value | Phase 11 ledger (cumulative net deposits) | USD minor units |
| `deposit_propensity` | Probability of depositing in next 7 days | Phase 11 + Phase 12 payment history | 0.0-1.0 |
| `bonus_sensitivity` | Responsiveness to bonus offers | Phase 13 bonus history | 0.0-1.0 |
| `rg_risk` | Responsible gambling risk score | Phase 14 RG records (limits, SE, distress) | 0.0-1.0 |

### Segment integration

Segments reference propensity features in their `definition` JSONB:
```json
{
  "churn_risk": {"gt": 0.7},
  "ltv": {"gt": 50000},
  "rg_risk": {"lt": 0.3}
}
```
Segment evaluation (ADR-0137) joins `propensity_feature` table on `(player_uuid, feature_name, model_version)`.

### ML model governance (EU AI Act — Phase 19 ADR-0123)

- Propensity models registered in `AIModel` table (Phase 19).
- **Risk classification: limited** (transparency obligations; player must know features used for marketing).
- **Linter rule 203:** every propensity feature has `model_version` NOT NULL (EU AI Act governance).
- **Linter rule 204:** propensity models registered in `AIModel` table (Phase 19 rule 171 extension).
- **Model documentation:** technical docs, risk assessment (per EU AI Act Annex IV for limited risk).
- **Model changes:** new `model_version`; recompute features; audit trail.
- **Player transparency:** privacy policy states features used for marketing; consent flow (Phase 9) includes propensity feature disclosure.
- **Linter rule 205:** player transparency — privacy policy states features used for marketing (EU AI Act limited risk).

## Alternatives

- **No propensity features** (rejected). Engagement use case requires targeting; without propensity, segments are demographic-only (low precision).
- **Unregistered ML models** (rejected). EU AI Act violation; Phase 19 linter rule 171.
- **Mutable features (in-place update)** (rejected). Loses audit trail; regulator asks "what was the player's churn_risk on date X?" — without versioning, cannot answer.
- **Cached features (no recompute)** (rejected). Features go stale; player who churns is still targeted as "low churn risk."
- **Free-form feature names** (rejected). Untestable; ungovernable. Closed catalog of 5 features is testable + governable.
- **No player transparency** (rejected). EU AI Act limited risk mandates transparency; failure to disclose is fineable.
- **High-risk classification (default)** (rejected). Propensity features are inputs, not decisions; limited risk is correct unless Q21 resolution upgrades.

## Consequences

- PropensityFeature model (insert-only per model_version).
- Nightly feature engineering job (Celery; 03:00 UTC).
- Feature catalog (5 features; closed enumeration).
- EU AI Act compliance (limited risk; transparency obligations).
- Propensity models registered in AIModel (Phase 19).
- Player transparency (privacy policy + consent flow).
- Linter rules 203, 204, 205.
- Open question OQ-ENG-001: propensity model vendor (in-house vs vendor; Q5-blocked).
- Open question OQ-ENG-002: propensity model recompute cadence (nightly recommended; OPEN).
- Open question OQ-ENG-006: propensity feature transparency (privacy policy wording; Q1-blocked).

## Validation Plan

- **Feature engineering test:** run nightly job; assert features computed for all active players; assert 5 features per player.
- **Feature store test:** query propensity_feature by (player, feature, model_version); assert correct value; assert insert-only (UPDATE raises).
- **Segment integration test:** segment with `{"churn_risk": {"gt": 0.7}}`; assert segment evaluation joins propensity_feature; assert only high-churn players included.
- **EU AI Act registration test (linter rule 204):** grep for propensity model usage; assert all models registered in AIModel (Phase 19).
- **Model version test (linter rule 203):** grep for propensity_feature; assert `model_version` NOT NULL on all rows.
- **Transparency test (linter rule 205):** grep privacy policy; assert states "propensity features used for marketing."
- **Feature catalog test:** attempt to create feature with name not in catalog; assert rejected.
