# ADR-0024 — CI pipeline (GitHub Actions)

## Context

Phase 3 introduces the first CI pipeline. CI must enforce: traceability linter rules 1–16, ruff linting (I, F401, E402, F403/F405), Django `check` and `check --deploy`, migrations on an ephemeral DB, pytest (harness present, suite may be empty), and OpenAPI drift detection.

## Decision

Adopt a single GitHub Actions workflow at `.github/workflows/ci.yml` that runs on every push and PR. The workflow: (1) installs Python + pinned deps; (2) runs `bash scripts/check_traceability.sh`; (3) runs `ruff check .`; (4) runs `python manage.py check && python manage.py check --deploy`; (5) starts Postgres 16 + Redis 7 services; (6) runs `python manage.py migrate` on the ephemeral DB; (7) runs `pytest`; (8) runs `python manage.py spectacular --file openapi.yaml` and diffs against the committed `docs/api/openapi.yaml`.

## Alternatives

Alternatives considered: (a) GitLab CI — different runner model; (b) Jenkins — self-hosted, higher maintenance; (c) no CI until Phase 4 — accumulates debt. (a) rejected for runner model; (b) rejected for maintenance; (c) rejected for debt accumulation.

## Consequences

CI runner cost is a Q5-blocked ASSUMED (see unresolved-decisions.md). CI runtime must stay under 10 minutes for developer ergonomics. Flaky tests block merges; must be fixed immediately.

## Validation Plan

Phase 3: CI green on trunk. Phase 4: CI runtime ≤ 10min p95. Phase 5: CI includes integration tests with real IdP stub.
