# ADR-0119 — Machine-Assembled Citations (Law 12; Claim-Level Grounding)

## Context

Law 12 (Law of Machine-Assembled Citations): The LLM never names a citation. The machine maps claims to retrieved chunk IDs and hard-validates the set. Hallucinated citations destroy trust.

The threat is hallucination. LLMs are probabilistic; when asked to cite sources, they frequently invent citations that look plausible but do not exist. A 2023 Stanford study found that GPT-4 hallucinated citations in 27% of responses when asked to cite sources — the citations had real-sounding author names, real-sounding journal names, and plausible page numbers, but the papers did not exist. In a legal/regulatory context (iGaming), a hallucinated citation is worse than no citation: it gives the player false confidence that the answer is sourced, when in fact the LLM invented both the answer and the source.

The mitigation is architectural: the LLM is forbidden from naming citations. The LLM outputs claims only ("The bonus wagering requirement is 20x."). A separate machine step (Claim-Level Grounder) maps each claim to the retrieved chunk IDs that support it. A final machine step (Citation Builder) attaches the real chunk IDs as citations. The LLM never touches citations; the machine validates every citation against the retrieved set.

## Decision

### Citation pipeline (Steps 5, 6, 9 of the 10-step RAG pipeline)

**Step 5: LLM Answer Composer**
- Outputs claims (structured: `{claim_id, claim_text, fact_references}`).
- **EXPLICITLY FORBIDDEN from naming citations** (Law 12).
- Prompt instructs: "Output claims only; do not cite sources; do not reference chunk IDs; do not say 'according to...'."
- Linter rule 168: no LLM prompt instructs the model to cite sources.
- Linter rule 169: no LLM response parsing extracts citations from model output.

**Step 6: Claim-Level Grounder**
- Maps each claim to retrieved chunk IDs.
- Two methods (configurable per query type):
  - **NLI (Natural Language Inference):** does the claim entail from the chunk? (e.g., DeBERTa-v3 NLI model; Q5-blocked OQ-AI-004).
  - **Span mapping:** does the claim text appear (or paraphrase) in the chunk? (e.g., sentence-level cosine similarity >0.85).
- Ungrounded claims (no supporting chunk) flagged for hard fail.

**Step 9: Machine-Assembled Citation Builder**
- Attaches real chunk IDs to grounded claims.
- Verifies chunk ID exists in the retrieved set (hard validation).
- Attaches as metadata: `{claim_id, chunk_ids: [...], grounding_confidence}`.
- Ungrounded claims: hard fail; safe fallback; no citation attached.

### LLM never names citations

- Linter rule 168: no LLM prompt instructs the model to cite sources. Grep scans all prompt templates for "cite", "citation", "source", "reference", "according to". Zero findings in instruction context.
- Linter rule 169: no LLM response parsing extracts citations from model output. Grep scans all response parsers for citation extraction patterns. Zero findings.
- Citations are ALWAYS machine-assembled from claim-level grounding.

### Citation display

- Rendered as footnotes/links to source chunks.
- Player can click to view the source chunk (read-only; tenant-scoped).
- Citation format: `[1]` superscript → footnote with chunk title + source URL.
- No LLM-generated citation text anywhere in the response.

### Grounding confidence

- NLI: probability score (0.0-1.0); threshold 0.7 (configurable).
- Span mapping: cosine similarity (0.0-1.0); threshold 0.85 (configurable).
- Below threshold = ungrounded = hard fail.

## Alternatives

- **LLM names citations** (rejected). Law 12 violation; hallucination risk. The Stanford study is the canonical evidence.
- **No citations** (rejected). Trust requires verifiability; players cannot verify claims without citations.
- **Document-level citations (not claim-level)** (rejected). Coarse; a claim may be supported by one chunk but the citation points to the whole document; player cannot verify the specific claim.
- **LLM names citations + machine validates** (rejected). The LLM still hallucinates; validation catches some but not all (a hallucinated citation that happens to match a real chunk ID is still a defect).
- **NLI only (no span mapping)** (rejected). NLI is computationally expensive; span mapping is faster for exact matches. Hybrid is best.
- **Span mapping only (no NLI)** (rejected). Span mapping misses paraphrases; NLI catches semantic entailment.
- **Soft pass for ungrounded claims** (rejected). Ungrounded claims = hallucination; must hard fail.

## Consequences

- Claim-level grounding required (Step 6 of RAG pipeline).
- Machine-assembled citations only (Step 9); LLM never names citations.
- Linter rules 168, 169 enforce LLM citation prohibition.
- NLI model required (Q5-blocked OQ-AI-004); span mapping as fallback.
- Ungrounded claims hard fail; safe fallback; no citation attached.
- Citation display: footnotes/links to source chunks; player can verify.
- Grounding confidence threshold configurable per query type.

## Validation Plan

- **Citation accuracy test:** grounded claims cite correct chunks; assert chunk IDs in citation match retrieved set.
- **Hallucination test:** ungrounded claims hard-fail; assert no citation attached; assert safe fallback.
- **LLM citation prohibition test (linter rule 168):** grep all prompt templates for citation instruction language; assert zero findings.
- **LLM citation prohibition test (linter rule 169):** grep all response parsers for citation extraction; assert zero findings.
- **NLI grounding test:** claim entailed from chunk → grounded; claim not entailed → ungrounded.
- **Span mapping test:** claim text appears in chunk → grounded; claim text absent → ungrounded.
- **Citation display test:** response rendered with footnotes; player can click to view source chunk.
- **Grounding confidence test:** claim below threshold → ungrounded → hard fail.
