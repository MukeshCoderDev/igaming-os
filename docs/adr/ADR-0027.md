# ADR-0027 — Testing & coverage (mypy gradual + coverage baseline + diff ≥80%)

## Context

Phase 4 introduces type checking and coverage enforcement. mypy from scratch on a large codebase is noisy; gradual typing with a strict module list is the practical path. Coverage baseline must be locked at Phase 4 achieved level; diff enforcement prevents regression. Branch coverage is mandatory from Phase 8.

## Decision

Adopt mypy gradual baseline. strict_modules = Phase 3+4 packages (noventra.settings, noventra.api, noventra.apps.core, noventra.observability, noventra.middleware, noventra.errors). List grows per phase. Linter rule 18 enforces the strict list is clean. Coverage baseline locked at Phase 4 achieved level (.coverage-baseline-phase4.txt). Diff ≥80% from Phase 4 onward. +5%/phase from Phase 5 (80%@10, 85%@15, 90%@20). Branch mandatory @8. Exclusions in pyproject [tool.coverage].

## Alternatives

Alternatives: (a) mypy strict from day 1 — too noisy; (b) pyright — different ecosystem; (c) no type checking — conflicts with NFR §7.1 testability; (d) 100% coverage always — unrealistic and gaming-prone. (a) rejected for noise; (b) rejected for ecosystem; (c) rejected for testability; (d) rejected for gaming.

## Consequences

Strict module list must be maintained (added per phase). Coverage baseline file must be committed; if it drifts, CI fails. Diff enforcement requires diff-cover or equivalent. Branch coverage at Phase 8 may surface legacy uncovered branches.

## Validation Plan

Phase 4: mypy strict list clean (rule 18). Phase 4: baseline locked; diff ≥80% on every PR. Phase 5: coverage 80%@10. Phase 8: branch coverage mandatory.
