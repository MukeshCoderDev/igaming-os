# ADR-0137 — Segment Model & RGPort Prefiltering (Law 2 Applied to Marketing)

## Context

Segments are the targeting input for campaigns. Without RGPort prefiltering, excluded/cooling-off players appear in segments and are caught only at send time — too late if the send is already queued. Law 2 (Prefiltered Isolation) applies to marketing: filter INSIDE the query, not after retrieval.

The 2022 UK GC enforcement (£3M, cited in Phase 20 ADR-0129) is the canonical example: the operator's segment query did not filter excluded players; the suppression was applied at send time only; a bug in the send-time filter caused 2,300 self-excluded players to receive bonus offers. The fix was not better send-time filters — it was prefiltering at the segment query level, so excluded players never enter the segment in the first place.

The Suppression Drift pain (blueprint §3) is the second threat: "Purged user gets email because flag was cached." If segments cache a `suppressed` boolean, a DSAR erasure that purges the player record may leave the cached flag stale (the player is gone but the flag says "not suppressed"), and a future campaign targeting the segment may attempt to send to a purged player. The cure is deterministic join at send time (ADR-0140) + no cached suppression in segments.

**Unique constraint:** `(segment_uuid, player_uuid)` — no duplicate memberships.

### RGPort prefiltering (Law 2 applied to marketing)

- Every segment query calls `RGPort.check_self_excluded` + `RGPort.check_cooling_off` for each candidate player.
- Excluded/cooling-off players filtered out BEFORE membership materialization (not after).
- **Linter rule 196:** segment queries include RGPort check (no post-retrieval filtering of excluded players).
- The check is per-player (not per-segment); a player who self-excludes mid-query is filtered out.

### Segment evaluation

- **Scheduled (nightly rebuild):** Celery job at 02:00 UTC; for each active segment, query candidates, apply RGPort prefilter, materialize to SegmentMembership.
- **On-demand:** admin trigger (for testing; for immediate segment refresh).
- **Materialized** to SegmentMembership table (not computed on read — segments are too large for on-read evaluation at scale).

### No cached suppression status

- Segments do NOT cache suppression/exclusion/cooling-off status (which would survive DSAR purge — the Suppression Drift pain).
- Suppression is checked at send time via MarketingGate deterministic join (ADR-0140).
- Segments cache only eligibility (demographics, behavior, propensity); suppression is always live.
- **Linter rule 200:** SegmentMembership does not include suppression flag (no cached suppression; Law 24).

## Alternatives

- **Post-retrieval filtering** (rejected). Law 2 violation; excluded players appear in segment briefly; a bug in the post-filter (like the 2022 UK GC incident) lets them through.
- **Cached suppression** (rejected). Suppression Drift pain; survives DSAR purge; purged user gets email.
- **On-read evaluation (no materialization)** (rejected). Too slow at scale (1M players × segment evaluation per query); materialization is the industry standard.
- **No RGPort prefiltering (send-time only)** (rejected). The 2022 UK GC incident showed send-time-only fails when the filter has a bug.
- **Per-segment RGPort check (not per-player)** (rejected). A player who self-excludes mid-query would be included if the segment was already evaluated; per-player check catches this.
- **Segment membership without TTL** (rejected). Stale memberships accumulate; players who no longer match the segment definition remain; TTL expires stale memberships.

## Consequences

- Segment + SegmentMembership models.
- RGPort prefiltering mandatory (linter rule 196).
- No cached suppression (linter rule 200).
- Nightly rebuild job (Celery; 02:00 UTC).
- On-demand evaluation (admin trigger).
- Segment TTL (configurable per segment; OQ-ENG-004).
- Open question OQ-ENG-004: segment membership expiry (TTL; configurable per segment; OPEN).

## Validation Plan

- **Segment evaluation test:** create segment with definition; run nightly rebuild; assert SegmentMembership materialized correctly.
- **RGPort prefiltering test:** segment with 100 candidates including 5 self-excluded + 3 cooling-off; run rebuild; assert 92 memberships (8 filtered out); assert excluded/cooling-off players NOT in SegmentMembership.
- **No-cached-suppression test (linter rule 200):** grep SegmentMembership schema; assert no `suppressed` / `excluded` / `cooling_off` boolean columns.
- **Nightly rebuild test:** trigger rebuild; assert all active segments evaluated; assert paused segments skipped.
- **On-demand evaluation test:** admin triggers segment refresh; assert SegmentMembership updated immediately.
- **Mid-query self-exclusion test:** player self-excludes during segment evaluation; assert player filtered out (per-player check).
- **TTL expiry test:** segment membership with past `expires_at`; assert membership removed on next rebuild.
