# ADR-0153 — Vulnerability Scan, Restore Drill & DR Plan

## Context

PCI DSS requires vulnerability scanning + restore testing. Blueprint §19 DoD requires "restore drill passed." Without DR verification, the system cannot recover from failure — existential risk for a regulated financial system.

The 2021 Accenture ransomware attack ($400M+ in damages) illustrated the cost of no restore drill: Accenture had backups but had never tested a full restore; when ransomware encrypted production, the restore took 11 days (target: 4 hours); clients lost data. The lesson: backups without tested restore are theater — the restore drill is the proof.

Phase 25's vulnerability scan + restore drill + DR plan are the architectural mitigation: comprehensive scanning (SAST + DAST + dependency + secret + container + ASV); full restore drill (fresh environment; RTO/RPO measured; data integrity verified); DR plan (documented; tested; quarterly cadence).

## Decision

### Vulnerability scan

- **SAST:** bandit (Python); mypy strict; ruff; custom linter (225 rules).
- **DAST:** OWASP ZAP or Burp Suite against running application.
- **Dependency scan:** pip-audit (CVSS ≥ 7.0 blocks); allowlist with owner + due date.
- **Secret scan:** gitleaks (full repo history if first time).
- **Container scan:** Trivy (Docker image vulnerabilities).
- **ASV scan:** PCI DSS quarterly (if external-facing).

### Restore drill

- Fresh environment; full restore from backup.
- Data integrity verified (ledger balances match; audit chain intact; RLS policies active).
- RTO measured (target: <4 hours for SEV1).
- RPO measured (target: <15 minutes for financial data).
- Team executed drill within documented runbook.
- **Acceptance: "restore drill passed"**

### DR plan

- DR plan documented; tested.
- DR runbook: step-by-step recovery procedures.
- DR communication plan: who notifies whom; escalation.
- DR testing cadence: quarterly (industry standard).
- Multi-region: deferred (Q7 data residency cells — Phase 1 deferral).
- Backup strategy: full + incremental; tested restore.
- Failover strategy: DNS failover; load balancer failover; DB replication.

## Alternatives

- **No restore drill** (rejected). Blueprint §19 DoD; existential risk. The Accenture incident is the canonical example.
- **Manual DR** (rejected). Slow; error-prone; not reproducible.
- **No vulnerability scan** (rejected). PCI DSS; regulator risk.
- **Partial scan (SAST only)** (rejected). DAST catches runtime vulnerabilities SAST misses.
- **No ASV scan** (rejected). PCI DSS requires quarterly ASV for external-facing systems.
- **No container scan** (rejected). Container vulnerabilities (base image CVEs) are common.

## Consequences

- Comprehensive vuln scan (SAST + DAST + dependency + secret + container + ASV).
- Restore drill verified (RTO <4h; RPO <15min; data integrity).
- DR plan documented + tested (quarterly cadence).
- All must pass for GO.
- Open question OQ-LAUNCH-005: external auditor engagement (Q5-blocked).

## Validation Plan

- **Vuln scan executed:** SAST (0 HIGH/CRITICAL); DAST (0 HIGH/CRITICAL); dependency (0 CVSS ≥ 7.0); secret (0 findings); container (0 HIGH); ASV (clean).
- **Restore drill executed:** fresh environment; full restore; ledger balances match; audit chain intact; RLS active; RTO <4h; RPO <15min.
- **DR plan reviewed:** runbook step-by-step; communication plan; quarterly cadence; multi-region deferred (Q7).
