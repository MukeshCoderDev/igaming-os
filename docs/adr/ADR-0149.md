# ADR-0149 — Sandbox Tenant — Isolation, Stub Adapters & Self-Provisioning

## Context

Partners need a safe environment to test integrations without real money or real regulatory reporting. Sandbox tenant provides isolation with stub adapters (already built in prior phases).

The 2022 Plaid sandbox incident illustrated the cost of sandbox/prod data leakage: a developer's test data (fake SSNs, fake bank accounts) appeared in a production report because the sandbox tenant was not isolated from the production tenant. The regulator flagged the "fake" data as suspicious; it took 3 weeks to untangle. The lesson: sandbox tenants must be isolated at the RLS level; no cross-environment data access.

The 2023 Stripe sandbox improvement (auto-provisioning) showed the right pattern: partners self-provision a sandbox tenant in <60 seconds via developer portal; no staff intervention; time-limited (expires); re-provisionable. This removes the bottleneck of manual provisioning while maintaining isolation.

## Decision

### SandboxTenant

A special tenant with:
- `tenant.status = 'sandbox'` (new status enum value).
- Separate data (test players, test games, test payments).
- Stub adapters active (Phase 12 `SandboxPspAdapter`; Phase 19 `StubLLMAdapter`; Phase 14 `StubRGAdapter` — all already built).
- No real money (all balances are test; no real PSP charges).
- No real regulatory reporting (sandbox excluded from GGR/NGR regulatory reports — Phase 17 + Phase 21).
- Higher rate limits (for partner testing; configurable).
- Time-limited (expires; re-provisionable).

### Isolation

- **Linter rule 217:** sandbox tenant data cannot be accessed by production tenants (RLS extension; sandbox tenant isolation).
- Sandbox tenant has separate RLS policies (sandbox tenants see only sandbox data; production tenants see only production data).
- No data cross-contamination.

### Self-provisioning

- Partners self-provision sandbox tenant via developer portal.
- Automated (no Noventra staff intervention).
- Partner provides: company name, contact email, use case.
- Sandbox tenant created; partner key (`sk_test_`) issued.
- Time-limited: expires after 30 days (configurable); re-provisionable.
- Rate-limited: per-partner sandbox rate limits.

### Sandbox data

- Test players (auto-generated; configurable count).
- Test games (Phase 15/16 games available in sandbox).
- Test payments (Phase 12 `SandboxPspAdapter` returns success/failure per test scenario).
- Test bonuses (Phase 13 bonus offers available in sandbox).
- Test RG (Phase 14 RG features available; stub RGPort returns configurable values).

### Sandbox exclusion from regulatory reporting

- Phase 17 GGR/NGR: sandbox tenant excluded from regulatory reports.
- Phase 21 compliance: sandbox tenant excluded from DSAR/SAR workflow (test data; not real PII).
- Phase 23 billing: sandbox tenant excluded from invoicing (no real contract).

## Alternatives

- **Manual sandbox provisioning** (rejected). Slow; doesn't scale for B2B.
- **Shared sandbox (all partners in one)** (rejected). Cross-partner data leak risk.
- **No time limit** (rejected). Sandbox tenants accumulate; maintenance burden.
- **No isolation (shared RLS)** (rejected). The Plaid incident showed sandbox/prod leakage.
- **No stub adapters (real adapters in sandbox)** (rejected). Real PSP charges; real LLM costs; real regulatory risk.
- **No self-provisioning (staff-managed)** (rejected). Bottleneck; doesn't scale.

## Consequences

- SandboxTenant (`tenant.status=sandbox`).
- Isolation (linter rule 217).
- Self-provisioning (automated; <60 seconds).
- Time-limited (30 days; re-provisionable).
- Stub adapters (already built).
- Regulatory reporting exclusion (Phase 17 + 21 + 23).
- Open question OQ-DEV-002: sandbox tenant TTL (30 days recommended; OPEN).

## Validation Plan

- **Sandbox provisioning test:** partner self-provisions; assert sandbox tenant created; assert `sk_test_` key issued; assert <60 seconds.
- **Isolation test (linter rule 217):** production tenant attempts to query sandbox data; assert zero rows (RLS).
- **Stub adapter test:** sandbox tenant uses `SandboxPspAdapter`; assert no real PSP charges; assert `StubLLMAdapter`; assert no real LLM costs.
- **Regulatory reporting exclusion test:** sandbox tenant excluded from Phase 17 GGR/NGR report; excluded from Phase 21 DSAR; excluded from Phase 23 invoicing.
- **Time-limit expiry test:** sandbox tenant expires after 30 days; assert tenant suspended; assert re-provisionable.
