# ADR-0154 — SLOs, Incident Response & Release Gates

## Context

Blueprint §11 specifies SLOs. Google SRE pattern: error budgets. Amazon COE: blameless postmortems. Without SLOs + incident response + release gates, the system cannot be operated safely in production.

The 2023 CrowdStrike incident (8.5M Windows hosts down; $5.4B in damages) illustrated the cost of no release gate: a configuration change was deployed without validation; the change caused a kernel panic on boot; 8.5M hosts blue-screened; airlines, hospitals, and banks went offline. The lesson: release gates are not optional — every deployment must pass a checklist before reaching production.

Phase 25's SLOs + incident response + 20 release gates are the architectural mitigation: SLOs define what "working" means; incident response defines what happens when it stops working; release gates define what must be true before launch.

## Decision

### SLOs (blueprint §11)

- Critical availability: 99.9% (initial) / 99.95% (growth) / 99.99% (global).
- RG Kill Switch Latency: <200ms (commit → WS disconnect) — regulator-mandated.
- CDN Invalidation: <1s for connected clients (Phase 22 real-time).
- Partner Webhook Delivery: 99.9% within 5s (Phase 24).
- Error budget: SLO budget exhaustion = feature freeze (Google SRE pattern).
- SLO monitoring: real-time dashboards; alerting on breach.
- SLO review: monthly; adjust if needed.

### Incident response

- Incident response plan: documented; tested.
- On-call rotation: 24/7 for production.
- Incident severity levels: SEV1 (outage); SEV2 (degraded); SEV3 (minor).
- Incident communication: internal (Slack); external (status page; regulator notification if required).
- Postmortem: blameless; root cause; corrective actions; 5 Whys (Amazon COE pattern).
- Incident runbooks: per service; per failure mode.
- Tabletop exercise: quarterly; simulate incident; verify response.

### Release gates (20 items)

1. All ADRs ACCEPTED with named human signatures (Phase 1-24 = 145+ ADRs).
2. All linter rules green (225 rules; 0 violations; deterministic).
3. All tests pass (unit + integration + concurrency + chaos + load + security).
4. Coverage ≥ 95% per module (Phase 11-24).
5. SLOs verified (availability 99.9%+; Kill Switch <200ms).
6. Restore drill passed (RTO/RPO within target; data integrity verified).
7. Vulnerability scan clean (no HIGH/CRITICAL open; or allowlisted with owner + due date).
8. PCI SAQ-A confirmed (no PAN anywhere; linter rules 81/82/88 green).
9. Named humans for all approver roles (16 roles).
10. Q1 (jurisdictions) resolved or explicitly accepted with documented deferral (DEC-0064).
11. Q5 (budget) resolved or explicitly accepted (DEC-0064).
12. All OPEN OQs resolved or documented with target phase.
13. Increment 1-5 close reports signed.
14. Legal hold matrix active (no active holds blocking launch).
15. Vendor registry all valid (no expired vendors; auto-suspend enforced).
16. Financial invariants hold under concurrency (6 invariants verified).
17. Isolation holds (cross-tenant zero rows under load).
18. Tipping-off prohibition verified (grep against REAL code; zero findings; non-vacuous).
19. AI Boundary verified (AI never writes domain truth; linter rule 175 against real code).
20. Conformance gate active (no production keys without conformance pass; ADR-0020 closure).

## Alternatives

- **No SLOs** (rejected). Blueprint §11; operational risk; cannot measure "working."
- **No incident response** (rejected). Production failures unhandled; regulator risk.
- **No release gates** (rejected). Launch risk; regulator risk. The CrowdStrike incident is the canonical example.
- **Fewer release gates** (rejected). Each gate covers a distinct risk; omitting any leaves a gap.
- **No error budgets** (rejected). Google SRE pattern; without error budgets, SLOs are aspirational not enforced.
- **No postmortem** (rejected). Without blameless postmortem, root causes are not addressed; incidents repeat.

## Consequences

- SLOs defined + monitored (availability; latency; error budgets).
- Incident response plan (on-call; severity; postmortem; tabletop).
- 20 release gates (all must be GREEN for GO).
- Kill Switch <200ms is regulator-mandated (non-negotiable).
- Error budget exhaustion = feature freeze (Google SRE pattern).
- Open question OQ-LAUNCH-006: launch communication plan (OPEN).

## Validation Plan

- **SLO dashboards verified:** real-time dashboards show availability 99.9%+; Kill Switch <200ms; error budget tracking.
- **Incident response tabletop:** simulate SEV1; verify on-call paged; verify communication plan; verify postmortem process.
- **Release gates checklist:** all 20 gates verified GREEN; each gate signed by named human.
- **Error budget test:** simulate SLO breach; assert feature freeze triggered.
