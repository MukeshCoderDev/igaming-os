# ADR-0096 — Realtime Seam — Extends Phase 14 Infrastructure

## Context

Phase 14 (DEC-0091, ADR-0091) pulled Phase 22 real-time infrastructure forward to meet the Kill Switch <200ms SLO. That work delivered an ASGI application, a Redis pub/sub layer, a `KillSwitchConsumer` WebSocket, and a connection registry. Phase 15 must extend this seam to carry game-session traffic: bet stream (player → server), outcome push (server → player), and disconnect-on-kill-switch (server → player). The seam must be a thin extension — not a parallel infrastructure — so that any future improvement to the real-time layer (back-pressure, sharding, observability) automatically benefits both kill switch and game sessions.

The alternative — a separate game-session WebSocket infrastructure — would double operational surface area, fragment connection accounting (so kill switch cannot enumerate live game sessions), and force two SLO budgets to be met independently.

## Decision

Phase 15 introduces a single new WebSocket consumer, `GameSessionConsumer`, that:
- Subclasses the same `AsyncJsonWebsocketConsumer` base as `KillSwitchConsumer`.
- Joins the same connection registry that the kill switch iterates to fan-out HALT signals. This means kill switch enumeration of "live game sessions to terminate" is O(1) lookup, not a separate query.
- Subscribes to the same Redis pub/sub channels used by the kill switch. Kill switch publishes `halt.tenant.<uuid>` and `halt.global`; the game-session consumer listens on the relevant channels and closes its connection with code 4001 ("kill_switch") on receipt.
- Publishes its own events on `game.round.<uuid>` for outcome push; the consumer for a given player listens on its own channel and pushes JSON to the client.

The seam is the contract: any new consumer added later (Phase 17+ chat, Phase 22 lobby) MUST join the same connection registry and listen on the same halt channels. This is enforced by linter rule 113 (Phase 15).

## Alternatives

- **Separate game-session infra** (rejected). Doubles operational surface; kill switch cannot enumerate game sessions; two SLO budgets.
- **HTTP long-polling** (rejected). Latency >200ms; violates kill switch fan-out SLO.
- **SSE** (rejected). Unidirectional; cannot accept bet stream.
- **No registry, broadcast halt** (rejected). O(N) broadcast on every kill switch; kills non-game sessions unnecessarily.

## Consequences

- All WebSocket consumers in the codebase share one connection registry. Adding a new consumer is cheap but requires registry registration.
- Redis pub/sub is the only fan-out channel. This is acceptable for Phase 15 volume; Phase 22 will revisit sharding.
- Disconnect-on-kill-switch is now a property of the seam, not of individual consumers. New consumers get it for free.
- Linter rule 113 (Phase 15) forbids any WebSocket consumer that does not subclass the base + join the registry.

## Validation Plan

- Connection-registry test: spawn a GameSessionConsumer + a KillSwitchConsumer; trigger kill switch; assert both connections close within 200ms.
- Pub/sub test: publish on `halt.tenant.<uuid>`; assert GameSessionConsumer receives and closes.
- Linter rule 113: grep for `AsyncJsonWebsocketConsumer` subclasses outside the registry pattern; assert zero violations.
- Concurrent-connection load test (Phase 14 `kill_switch_load_test.py` extended): 1000 game sessions + 1 kill switch trigger; assert p99 disconnect <200ms.
