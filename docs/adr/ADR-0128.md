# ADR-0128 — Execution Logs (Audit Trail; Link to LLM Calls + Correlation_ID)

## Context

Every agent action must be auditable. Law 9 (Immutable Audit) applies to agent execution. Without execution logs, a regulator inquiry asks "what did the Fraud/AML agent do on 2026-03-15?" and the answer is "we don't know" because the agent's actions were not recorded. The 2024 e-commerce refund incident (cited in ADR-0125) was partly an audit failure: the agent's actions were logged in application logs (rotated weekly) but not in an immutable audit trail; by the time the company investigated, the logs were gone.

Phase 20's execution logs are the immutable audit trail for agent actions. Every tool call — success, failure, denial, pending approval, expired — is recorded with:
- Tool name + input + output (what was done)
- Status + duration (outcome + performance)
- Correlation_id (Phase 4 — end-to-end trace from user request to tool execution)
- LLM call link (Phase 19 — which LLM call generated this tool call)
- Approval link (Phase 20 ADR-0127 — which approval authorized this execution, if high-risk)
- Error message (if failed)

The logs are insert-only (Law 9; Phase 7 pattern); UPDATE and DELETE are forbidden at the DB layer. The logs are hash-chained into the operational audit chain (Phase 7) so tampering is detectable.

## Decision

### AgentExecutionLog model

| Field | Type | Notes |
|---|---|---|
| `log_uuid` | UUID PK | |
| `tenant_uuid` | UUID | Tenant scope (RLS) |
| `agent_uuid` | UUID FK → AgentDefinition | The agent that executed |
| `tool_name` | str | The tool called |
| `input` | JSONB | Tool input (what the agent wanted to do) |
| `output` | JSONB | Tool output (nullable if denied/failed) |
| `status` | enum | success, failed, denied, pending_approval, expired |
| `duration_ms` | int | Execution duration |
| `correlation_id` | UUID | Phase 4 — end-to-end trace |
| `llm_call_id` | UUID | Phase 19 link (nullable if no LLM involved) |
| `approval_id` | UUID FK → AgentApproval | Phase 20 ADR-0127 link (nullable if low-risk) |
| `error_message` | TEXT | Nullable (if failed) |
| `created_at` | datetime | auto_now_add |

### Every agent action logged

- **Tool called** (`tool_name`)
- **Input** (`input` JSONB — what the agent wanted to do)
- **Output** (`output` JSONB — filled after execution; null if denied/pending/failed)
- **Status** (success/failed/denied/pending_approval/expired)
- **Duration** (`duration_ms`)
- **Correlation_id** (Phase 4 — end-to-end trace from user request → LLM call → tool call → execution → audit event)
- **LLM call link** (Phase 19 — which LLM call generated this tool call; nullable if no LLM involved, e.g., scheduled agent with deterministic tool)
- **Approval link** (Phase 20 ADR-0127 — which approval authorized this execution; nullable if low-risk)
- **Error message** (if failed)

### Immutable (Law 9)

- Insert-only per Phase 7 pattern.
- DB trigger `BEFORE UPDATE` raises; `BEFORE DELETE` raises.
- Corrections require a new log entry (negative entry for reversal; never mutation of original).
- **Linter rule 184:** agent execution log is immutable (insert-only; Law 9).

### Audit integration (Phase 7)

- Every execution generates an audit event:
  - `agent.tool_executed` (status=success)
  - `agent.tool_denied` (status=denied — forbidden tool or approval rejected)
  - `agent.tool_pending_approval` (status=pending_approval)
  - `agent.tool_expired` (status=expired — SLA breach)
  - `agent.tool_failed` (status=failed — execution error)
- Hash-chained into operational audit chain (Phase 7 pattern).

### Query capabilities

- **Per agent:** all executions by `agent_uuid`.
- **Per tool:** all executions by `tool_name`.
- **Per player:** all agent actions affecting player (via `input` JSONB player_uuid field).
- **Per correlation_id:** end-to-end trace (LLM call → tool call → execution → audit event).
- **Per approval:** all executions authorized by a specific approval.
- **Per LLM call:** all tool calls generated by a specific LLM call.

## Alternatives

- **No execution logs** (rejected). Law 9 violation; not auditable. The 2024 e-commerce incident is the canonical audit failure.
- **Application logs (not DB)** (rejected). Rotated; not immutable; not queryable; not hash-chained.
- **Separate from Phase 7 audit** (rejected). Duplication; use Phase 7 infrastructure (hash chain, RLS, insert-only trigger).
- **Mutable logs (allow correction)** (rejected). Law 9 mandates immutable; mutation destroys audit trail.
- **No correlation_id link** (rejected). Cannot trace end-to-end; regulator inquiry cannot reconstruct what happened.
- **No LLM call link** (rejected). Cannot trace which LLM output generated which tool call; hallucination debugging impossible.
- **No approval link** (rejected). Cannot trace which human approved which execution; accountability lost.

## Consequences

- AgentExecutionLog model (insert-only; hash-chained into Phase 7 audit).
- Every agent action logged (5 statuses).
- Linked to LLM calls (Phase 19) + correlation_id (Phase 4) + approvals (Phase 20 ADR-0127).
- Queryable per agent/tool/player/correlation_id/approval/LLM call.
- Linter rule 183: every agent action logged.
- Linter rule 184: execution log immutable (insert-only).
- Linter rule 185: every execution links to correlation_id + llm_call_id (end-to-end traceability).

## Validation Plan

- **Execution log test (every action logged):** invoke an agent; assert log entry created with correct tool_name + input + output + status + duration + correlation_id + llm_call_id.
- **Immutability test (UPDATE/DELETE raises):** attempt to UPDATE a log entry; assert DB raises; attempt to DELETE; assert DB raises.
- **Link test (LLM call + correlation_id + approval):** invoke high-risk tool via LLM; assert log entry links to LLM call ID + correlation_id + approval ID.
- **Query test (per agent/tool/player/correlation_id):** query logs by each dimension; assert correct results.
- **Status coverage test:** trigger each status (success, failed, denied, pending_approval, expired); assert log entry with correct status.
- **Hash chain test:** verify log entries are hash-chained into Phase 7 audit chain; tamper with a log entry; assert chain breaks.
- **Linter rule 183 test:** grep for agent tool execution code; assert each creates a log entry.
- **Linter rule 184 test:** grep for UPDATE/DELETE on agent_execution_log; assert zero matches.
- **Linter rule 185 test:** grep for log entry creation; assert each includes correlation_id + llm_call_id.
