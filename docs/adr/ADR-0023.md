# ADR-0023 — Settings split + named-var loud failure

## Context

Django settings must be split across environments (base, local, test, production) so that production never inherits dev defaults. Required environment variables must fail loudly (named variable, non-zero exit) before any database or network call. Secrets must never appear in code or config files — only in the environment.

## Decision

Split settings into `noventra/settings/{base,local,test,production}.py`. Define a required-variables list in `base.py`. At import time, validate every required variable is present; if any is missing, print a message naming the variable and `sys.exit(1)` before any DB or network call. Secrets (SECRET_KEY, DATABASE_URL, REDIS_URL, etc.) are read from environment variables only — never from files, never from Django settings defaults. Document the full variable list in `docs/architecture/settings-split.md`.

## Alternatives

Alternatives considered: (a) single settings.py with if/else — hard to audit; (b) django-environ only (no split) — doesn't enforce split; (c) dynamic settings from DB — chicken-and-egg at startup. (a) rejected for auditability; (b) rejected for no split; (c) rejected for chicken-and-egg.

## Consequences

Developers must set environment variables before running any command. `.env.example` must be kept in sync with the required list. Production deploys must inject all required variables via the orchestrator (k8s secrets, ECS, etc.).

## Validation Plan

Phase 3: missing `SECRET_KEY` in production → `sys.exit(1)` with named message before DB connection. Phase 3: `.env.example` covers every required variable (linter rule 13 enforces). Phase 4: production deploy fails fast on missing variable.
