# ADR-0132 — Evidence Repository — Immutable Storage, Retention & Access Audit

## Context

Compliance evidence is the artifact set auditors review. Must be immutable (Law 9; SEC 17a-4 WORM — Write Once Read Many). Retained 5-10 years per regulatory requirement. Every access audited.

The threat is evidence tampering. In 2021, a financial services firm was fined $70M by the SEC for altering audit evidence: the compliance team edited audit screenshots to hide control failures before the regulator's review. The WORM storage mandate (SEC 17a-4) exists precisely because mutable evidence cannot be trusted. Law 9 (Immutable Audit) extends this principle to all compliance evidence.

The second threat is unaudited access. If compliance evidence can be viewed without a log, a malicious insider can exfiltrate evidence (player PII, financial records, SAR narratives) without detection. The EvidenceAccessLog is the mitigation: every access (who, when, why) is recorded immutably.

Phase 21's evidence repository uses Phase 10's storage port (WORM; insert-only) for the evidence artifacts themselves, plus a ComplianceEvidence model for metadata + an EvidenceAccessLog for access audit. Retention is 5-10 years per jurisdiction (OQ-COMP-002); legal hold (ADR-0136) suspends destruction during litigation.

## Decision

### ComplianceEvidence model

| Field | Type | Notes |
|---|---|---|
| `evidence_uuid` | UUID PK | |
| `tenant_uuid` | UUID | Tenant scope (RLS) |
| `control_uuid` | UUID FK → ComplianceControl | The control this evidence supports |
| `evidence_type` | enum | policy_doc, test_result, screenshot, log_export, audit_report, cert, training_record |
| `evidence_url` | TEXT | Phase 10 storage port URI (immutable WORM) |
| `evidence_date` | date | When the evidence was collected |
| `collected_by` | str | Named human |
| `status` | enum | current, superseded, archived |
| `superseded_by` | UUID FK → ComplianceEvidence (nullable) | Link to newer evidence |
| `created_at` | datetime | auto_now_add |
| `updated_at` | datetime | auto_now |

### Immutability

- Evidence stored via Phase 10 storage port (WORM; insert-only).
- Cannot be mutated or deleted (except per retention schedule + legal hold exception).
- The `evidence_url` points to an immutable artifact; the metadata (ComplianceEvidence row) can be updated only for `status` transitions (current → superseded → archived).
- **Linter rule 192:** every compliance evidence has `evidence_url` (Phase 10 storage port; immutable).

### Retention

- Per regulatory requirement (5-10 years; OQ-COMP-002 Q1-blocked for specific periods).
- Retention enforcement job (Phase 9 pattern) checks `evidence_date`; on expiry, archives (does not delete — evidence retained for legal hold per ADR-0136).
- Archived evidence: `status=archived`; retained but not actively queried; accessible only via compliance officer + external auditor roles.
- Legal hold (ADR-0136) suspends archival/destruction; held evidence retained until hold released.

### Access audit

Every evidence access logged. **EvidenceAccessLog model:**
- `log_uuid` UUID PK
- `evidence_uuid` FK → ComplianceEvidence
- `accessed_by` str (named human)
- `accessed_at` datetime
- `purpose` TEXT (why the access)
- `created_at` datetime

**Immutable (Law 9):** insert-only per Phase 7 pattern; trigger BEFORE UPDATE/DELETE raises.
**Linter rule 193:** every evidence access logged in `evidence_access_log`.

### Supersession

- When new evidence supersedes old, old evidence `status=superseded` (not deleted); `superseded_by` links to new evidence.
- Supersession is audited (Phase 7 event `compliance.evidence_superseded`).
- Superseded evidence retained for audit; not actively queried but accessible.

## Alternatives

- **Mutable evidence** (rejected). Law 9 violation; SEC 17a-4 violation; the 2021 SEC fine is the canonical example.
- **No access audit** (rejected). Auditors require access trail; unaudited access allows exfiltration.
- **Evidence in DB (not storage port)** (rejected). DB blobs are mutable; Phase 10 storage port is WORM.
- **Delete on expiry (no archive)** (rejected). Legal hold may require evidence beyond retention; archive preserves without active query.
- **No supersession (replace in place)** (rejected). Loses audit trail; regulator asks "what did the evidence look like before the change?"
- **Shared evidence across controls** (rejected). Each control's evidence is distinct; sharing conflates audit trails.

## Consequences

- ComplianceEvidence model with Phase 10 storage port integration.
- EvidenceAccessLog model (immutable; Law 9).
- Retention with legal-hold exception (ADR-0136).
- Supersession (not deletion) for evidence updates.
- Linter rule 192: every evidence has `evidence_url`.
- Linter rule 193: every evidence access logged.
- Open question OQ-COMP-002: evidence retention period per jurisdiction (Q1-blocked).

## Validation Plan

- **Immutability test:** attempt to mutate evidence artifact in storage port; assert rejected (WORM); attempt to delete; assert rejected.
- **Access audit test:** access evidence; assert EvidenceAccessLog created with `accessed_by` + `accessed_at` + `purpose`; assert log immutable (UPDATE/DELETE raises).
- **Supersession test:** create evidence v1; supersede with v2; assert v1 `status=superseded`, `superseded_by=v2`; assert v1 retained (not deleted); assert v2 `status=current`.
- **Retention + legal-hold test:** evidence past retention; legal hold active; assert evidence NOT archived (hold suspends); release hold; assert evidence archived.
- **Linter rule 192 test:** grep for ComplianceEvidence; assert all have `evidence_url`.
- **Linter rule 193 test:** grep for evidence access code; assert all create EvidenceAccessLog.
