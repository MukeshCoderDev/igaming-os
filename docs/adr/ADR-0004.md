# ADR-0004 — OIDC for identity federation

## Context

Default tenants require standards-based federation that supports modern auth flows (authorization code, PKCE, refresh tokens). SAML is heavy for greenfield tenants and lacks first-class support for mobile and SPA clients. MB-REQ-0003 mandates that the identity service is the sole issuer of auth tokens.

## Decision

Adopt OpenID Connect (OIDC) as the default federation protocol. The identity service is the sole issuer of auth tokens (MB-REQ-0003) and supports OIDC authorization-code flow with PKCE for all clients. Token lifetimes are short (≤ 1h access, ≤ 30d refresh) per NFR §1.3.

## Alternatives

Alternatives considered: (a) SAML-only — excludes mobile/SPA clients and modern IdPs; (b) OAuth 2.0 without OIDC — no standardized user info; (c) custom token format — locks out third-party IdPs. (a) rejected for client coverage; (b) rejected for missing identity layer; (c) rejected for vendor lock-in.

## Consequences

Requires running an OIDC provider (or integrating with one). Discovery and JWKS rotation add operational complexity. Token revocation is harder than session-based auth.

## Validation Plan

Phase 4: integrate with two reference IdPs (Auth0, Keycloak) and verify interop. Phase 5: penetration test of the OIDC flow including token replay, code injection, and PKCE downgrade. Phase 7: load-test token issuance at 1k req/s.
