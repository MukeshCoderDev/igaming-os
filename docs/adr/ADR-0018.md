# ADR-0018 — Read models rebuildable from events

## Context

Read models (projections) drift over time as bugs are found and fixed. Without a rebuild path, drift becomes permanent and read models diverge from the source of truth (DEC-0001).

## Decision

All read models are projections from the event log. A rebuild command exists for each read model that re-derives it from the event log. Rebuilds are idempotent and may be run at any time without downtime.

## Alternatives

Alternatives considered: (a) read models with manual sync — drifts; (b) read models with periodic reconciliation — detects drift but doesn't fix it; (c) read models from a CDC stream — couples to database internals. (a) rejected for drift; (b) rejected for no fix; (c) rejected for coupling.

## Consequences

Rebuild is O(N) in event log size; for very large logs, rebuild takes hours. Rebuilds consume compute and I/O; must be scheduled. Read models may lag the event log by seconds during normal operation.

## Validation Plan

Phase 8: implement; verify that a rebuild produces identical state to the live read model. Phase 9: load-test rebuild at 10M events. Phase 10: verify zero-downtime rebuild.
