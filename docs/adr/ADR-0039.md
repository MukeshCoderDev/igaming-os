# ADR-0039 — Audit read API + clearance model + meta-audit cut-off

## Context

The audit log must be readable for compliance, forensics, and tenant self-service. Different readers have different clearance: tenant admins see only their own tenant's events; compliance officers see all events; external auditors see redacted events. The read API itself generates audit events (audit.read_performed) — but this must not recurse infinitely (a meta-meta-audit event for the read of the read event).

## Decision

Adopt a clearance model with three levels: (1) tenant_admin — sees events where tenant_id = requesting user's tenant; (2) compliance_officer — sees all events (unredacted); (3) external_auditor — sees all events but with PII redacted per ADR-0037. Cursor-based pagination (no offset; cursor = (created_at, event_uuid)). Filtering by event_type, actor_id, target_id, time range, correlation_id. Meta-audit cut-off: the audit.read_performed event is itself audited, but the audit of a read does NOT generate a further audit event (cut-off at depth 1). Implemented via a context flag (audit._meta_audit_depth) that prevents recursion.

## Alternatives

Alternatives: (a) offset-based pagination — slow at high offsets; (b) no clearance model (all readers see all) — security risk; (c) infinite meta-audit recursion — unbounded growth; (d) no meta-audit (reads not audited) — repudiation risk. (a) rejected for performance; (b) rejected for security; (c) rejected for unbounded growth; (d) rejected for repudiation.

## Consequences

Cursor pagination requires stable sort (created_at + event_uuid). Compliance officer role must be distinct from tenant admin (no tenant admin should see cross-tenant). External auditor redaction adds CPU per read. Meta-audit cut-off is a deliberate information loss (the audit of a read is audited, but the audit of that audit is not — acceptable trade-off).

## Validation Plan

Phase 7: clearance model enforcement test (tenant admin sees only own; compliance sees all; external auditor sees redacted). Phase 7: meta-audit cut-off test (read generates 1 audit event, not 2). Phase 7: cursor pagination test. Phase 8: load-test read at 100 concurrent queries.
