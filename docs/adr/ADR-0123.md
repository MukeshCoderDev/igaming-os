# ADR-0123 — EU AI Act Model Inventory (Risk Classification; Unacceptable Prohibited)

## Context

The EU AI Act (Regulation (EU) 2024/1689, in force August 2024, fully applicable August 2026) classifies AI systems by risk level:
- **Minimal risk:** no additional obligations (e.g., spam filters).
- **Limited risk:** transparency obligations (user must know they're interacting with AI).
- **High risk:** additional compliance documentation (technical docs, risk assessment, conformity declaration, logging, human oversight).
- **Unacceptable risk:** PROHIBITED (e.g., social scoring, real-time biometric identification in public spaces, manipulation via subliminal techniques).

Using an unacceptable-risk AI system is a criminal offence under the EU AI Act, with fines up to €35M or 7% of global annual turnover (whichever is higher). Using a high-risk system without the required documentation is a fineable offence (up to €15M or 3% of turnover).

Q21 (EU AI Act classification of retention AI) is OPEN: the retention AI (Phase 9 player retention) may be classified as high-risk if it makes automated decisions affecting players. The default is high-risk until proven otherwise; must be resolved before production.

Phase 19 mandates a model inventory: every LLM model registered in the `AIModel` table with risk classification; unacceptable-risk models prohibited at the linter level (rule 170); unregistered models prohibited (rule 171).

## Decision

### AIModel model

| Field | Type | Notes |
|---|---|---|
| `model_uuid` | UUID PK | |
| `provider` | str | e.g., `openai`, `anthropic`, `google`, `local` |
| `model_name` | str | e.g., `gpt-4o`, `claude-3-5-sonnet` |
| `version` | str | e.g., `2024-08-06` |
| `risk_classification` | enum | minimal, limited, high, unacceptable |
| `intended_use` | TEXT | e.g., "RAG answer composition for player support" |
| `documentation_url` | TEXT | Link to technical documentation |
| `technical_docs_url` | TEXT | EU AI Act Annex IV technical documentation |
| `risk_assessment_url` | TEXT | Risk assessment document |
| `conformity_declaration_url` | TEXT | Conformity declaration (high-risk only) |
| `status` | enum | approved, suspended, prohibited |
| `created_at` | datetime | auto_now_add |
| `updated_at` | datetime | auto_now |

**Unique constraint:** `(provider, model_name, version)` — no duplicate models.

### EU AI Act compliance

- **Unacceptable risk:** PROHIBITED. Linter rule 170: no AIModel with `risk_classification = unacceptable` can be used. Hard fail at the gateway.
- **High risk:** additional compliance documentation required (technical docs per Annex IV, risk assessment, conformity declaration). Linter rule: high-risk models must have non-null `technical_docs_url`, `risk_assessment_url`, `conformity_declaration_url`.
- **Limited risk:** transparency obligations (user must know they're interacting with AI). UI must display "AI-generated response" disclaimer.
- **Minimal risk:** no additional obligations.

### Model inventory

- Every LLM provider/model/version registered in `AIModel` table.
- Cannot use unregistered model (linter rule 171: every LLM call uses registered AIModel).
- Risk classification per EU AI Act (Q1-blocked for specific classifications; default to high-risk until proven otherwise).
- Compliance Officer + Legal Counsel review required for classification.

### Documentation per model

- **Technical documentation** (per EU AI Act Annex IV): description of the system, development process, monitoring, technical file.
- **Risk assessment:** identified risks, mitigation measures, residual risk.
- **Conformity declaration** (high-risk only): declaration of conformity with EU AI Act requirements.
- **Logging of model changes:** every model version change logged (Phase 7 audit).

### Q21 (EU AI Act classification of retention AI)

- OPEN; default to high-risk; resolve before production (OQ-AI-003).
- Retention AI (Phase 9) makes automated decisions about player retention (offers, communications). Under EU AI Act, this may be high-risk if it affects players' rights.
- Legal Counsel review required before classification.

## Alternatives

- **No model inventory** (rejected). EU AI Act mandates; fines up to €35M.
- **Self-classification only (no Compliance + Legal review)** (rejected). Classification requires legal judgment; self-classification by engineers is not defensible.
- **Default to minimal risk** (rejected). Conservative default is high-risk; downgrading requires evidence.
- **No prohibition on unacceptable-risk** (rejected). EU AI Act prohibits; using them is a criminal offence.
- **No documentation URLs** (rejected). EU AI Act Annex IV mandates technical documentation; URLs are the audit trail.
- **Permissive (allow unregistered models)** (rejected). Unregistered models have no risk classification; cannot verify compliance.

## Consequences

- AIModel registry required.
- EU AI Act compliance (4 risk classifications; unacceptable prohibited).
- Documentation per model (technical docs, risk assessment, conformity declaration).
- Q21 OPEN (retention AI classification; default high-risk).
- Linter rule 170: no unacceptable-risk model can be used.
- Linter rule 171: every LLM call uses registered AIModel.
- Compliance Officer + Legal Counsel review required for classification.
- Open question OQ-AI-003: Q21 EU AI Act classification of retention AI (Q1-BLOCKED).

## Validation Plan

- **Model inventory test:** register a model; assert it appears in AIModel table; assert unique constraint.
- **Unacceptable-risk prohibition test (linter rule 170):** register an unacceptable-risk model; attempt to use it; assert hard fail at gateway.
- **High-risk documentation test:** register a high-risk model; assert `technical_docs_url`, `risk_assessment_url`, `conformity_declaration_url` are non-null.
- **Unregistered model prohibition test (linter rule 171):** attempt to use an unregistered model; assert hard fail at gateway.
- **Q21 resolution tracking test:** verify OQ-AI-003 is tracked; default high-risk; assert resolution required before production.
- **Transparency obligation test:** limited-risk model used in chat; assert UI displays "AI-generated response" disclaimer.
- **Linter rule 170 test:** grep for AIModel usage; assert none with `risk_classification = unacceptable`.
- **Linter rule 171 test:** grep for LLM call code; assert each references a registered AIModel.
