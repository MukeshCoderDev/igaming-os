# ADR-0146 — Billing Change Audit — Phase 7 Continuity, Hash-Chained & Immutable

## Context

Law 9 (Immutable Audit): audit rows are insert-only and hash-chained. Billing changes (fee schedule changes, contract amendments, invoice voids, credit notes) are financial events that must be auditable for regulators and external auditors. Without billing audit, revenue changes are opaque.

The 2020 Wirecard scandal (€1.9B missing) illustrated the cost of opaque billing: the operator's billing system had no audit trail for invoice modifications; insiders could void invoices without detection; €1.9B in receivables was fabricated. The scandal destroyed the company. The lesson: every billing mutation must be audited, immutable, and hash-chained — so tampering is detectable.

Phase 23's billing audit extends Phase 7's operational audit chain to cover 16 billing-specific event types. The audit events are insert-only (trigger BEFORE UPDATE/DELETE raises) and hash-chained (SHA-256, Merkle-style, per Phase 7 ADR-0035). The `noventra_auditor` role (Phase 11 ADR-0065) has SELECT access for periodic external audit review.

## Decision

### Billing audit integration (Phase 7 extension)

**Event type taxonomy (16 new `billing.*` events):**

| Event | Trigger |
|---|---|
| `billing.contract_created` | New contract created |
| `billing.contract_amended` | New ContractVersion (amendment) |
| `billing.contract_suspended` | Contract status → suspended |
| `billing.contract_terminated` | Contract status → terminated |
| `billing.fee_schedule_created` | New FeeSchedule created |
| `billing.fee_schedule_changed` | New FeeSchedule version (change) |
| `billing.invoice_generated` | Invoice generated (scheduled job) |
| `billing.invoice_sent` | Invoice delivered to operator |
| `billing.invoice_paid` | Invoice payment received (Phase 12) |
| `billing.invoice_voided` | Invoice voided (correction) |
| `billing.invoice_disputed` | Operator disputes invoice |
| `billing.credit_note_issued` | Credit note issued (reversal) |
| `billing.statement_generated` | Operator statement generated |
| `billing.statement_sent` | Statement delivered |
| `billing.statement_acknowledged` | Operator acknowledges receipt |
| `billing.reconciliation_mismatch` | Invoice/statement reconciliation failed |

### Every billing mutation generates audit event

- **Linter rule 207:** every billing mutation (contract/fee_schedule/invoice/credit_note/statement) generates Phase 7 audit event.
- Audit event includes: `actor` (human or service), `action`, `entity_type`, `entity_id`, `before_state`, `after_state`, `correlation_id`, `timestamp`.

### Hash-chained

- Billing events hash-chained into operational audit chain (Phase 7 ADR-0035).
- Same infrastructure (SHA-256, Merkle-style, pgbouncer-compatible).
- Chain verifier extended to cover billing events.
- **Linter rule 215:** billing audit events hash-chained into Phase 7 operational audit chain.

### Immutable

- Billing audit events insert-only per Phase 7 pattern (trigger BEFORE UPDATE/DELETE raises).
- Billing records themselves (contracts, fee schedules, invoices) are versioned/immutable per their ADRs.

### Retention

- Billing audit events retained per Phase 7 operational retention (7+ years; Q1-blocked for specific periods).
- Financial contracts retained per Phase 9 retention (7+ years).
- Invoices retained per financial regulations (7+ years; Q1-blocked).
- Open question OQ-COMM-004: contract retention period per jurisdiction (7+ years; Q1-blocked).

### External auditor access

- `noventra_auditor` role (Phase 11 ADR-0065) has SELECT on billing audit events.
- Periodic external audit review (Phase 21 ComplianceReview).
- External auditor can query: "show me all billing changes between date X and date Y" → returns hash-chained events.

## Alternatives

- **No billing audit** (rejected). Law 9 violation; financial opacity; regulator risk. The Wirecard scandal is the canonical example.
- **Separate billing audit chain** (rejected). Duplication; use Phase 7 infrastructure (hash chain, RLS, insert-only trigger).
- **Mutable audit events** (rejected). Law 9 mandates immutable; mutation destroys audit trail; tampering undetectable.
- **No hash chain** (rejected). Without hash chain, tampering is undetectable; insert-only alone is insufficient (a privileged user can drop + recreate the trigger).
- **No external auditor access** (rejected). External auditor cannot verify; regulator inquiry cannot be answered.
- **Fewer event types** (rejected). Each event type captures a distinct financial event; omitting any leaves an audit gap.

## Consequences

- 16 new `billing.*` event types in Phase 7 audit chain.
- Linter rule 207: every billing mutation generates audit event.
- Linter rule 215: billing events hash-chained into Phase 7 operational audit chain.
- `noventra_auditor` role SELECT access.
- 7+ year retention (Phase 7 + Phase 9).
- External auditor periodic review (Phase 21 ComplianceReview).
- Open question OQ-COMM-004: contract retention period per jurisdiction (Q1-blocked).

## Validation Plan

- **Audit event generation test (each of 16 types):** trigger each billing mutation; assert audit event generated with correct `actor` + `action` + `entity_type` + `entity_id` + `before_state` + `after_state` + `correlation_id` + `timestamp`.
- **Hash-chain integrity test:** generate 100 billing events; verify hash chain; tamper with one event; assert chain breaks.
- **Immutability test:** attempt to UPDATE a billing audit event; assert DB raises; attempt to DELETE; assert DB raises.
- **External auditor access test:** `noventra_auditor` role queries billing audit events; assert SELECT succeeds; assert non-auditor role denied.
- **Retention test:** attempt to delete billing audit event <7 years old; assert rejected.
- **Linter rule 207 test:** grep for billing mutation code (contract/fee_schedule/invoice/credit_note/statement); assert each generates audit event.
- **Linter rule 215 test:** grep for billing audit event insertion; assert hash chain integration.
