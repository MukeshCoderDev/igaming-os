# ADR-0142 — Contract Model — B2B Operator Contracts, Versioning & Lifecycle FSM

## Context

DEC-0024 (HUMAN-APPROVED B2B OS provider business model) requires commercial contracts with operators. Without versioned contracts, billing cannot determine which fee schedule applies to which period. iGaming operators are licensed in multiple jurisdictions — contracts may span jurisdictions.

The 2023 GAN/Tabcorp contract dispute (A$45M) illustrated the cost of unversioned contracts: the operator and the platform provider disagreed on whether a 2021 email amendment (reducing rev-share from 15% to 12%) was binding. The contract had been amended via email; there was no version history; both parties produced different "current" versions. The court required a 14-month forensic reconstruction of email threads to determine the effective rate. The lesson: contracts must be versioned with effective dates, and billing must use the version effective at the billing period — not the current version.

Phase 23's contract model is the architectural mitigation: every amendment creates a new ContractVersion (new row; old version retained); billing uses the version effective at the billing period; every transition is audited (Phase 7). HUMAN-APPROVED per Phase 1 rule 5 (Business/Legal decisions require Legal Counsel + CFO signatures).

### Contract versioning

- Every amendment creates a new ContractVersion (new row; old version retained).
- Old versions retained per Phase 9 retention (7+ years for financial contracts).
- Billing uses the contract version effective at the billing period (not current).
- **ContractVersion model:**
  - `version_uuid` UUID PK
  - `contract_uuid` FK → Contract
  - `version_number` int
  - `snapshot` JSONB (full contract state at this version)
  - `effective_from` date
  - `effective_until` date (nullable; NULL = current)
  - `amended_by` str (named human)
  - `amendment_reason` TEXT
  - `created_at` datetime
- **Unique constraint:** `(contract_uuid, version_number)`.

### Lifecycle FSM

```
draft → active (signed; HUMAN-APPROVED)
active → suspended (breach; non-payment; regulatory action)
suspended → active (resolved)
active/suspended → terminated (contract ended; HUMAN-APPROVED)
active/suspended/terminated → expired (end_date reached)
```

Every transition audited per Phase 7.

### Jurisdiction scope

- Contract may span multiple jurisdictions (operator licensed in UK + MGA + NJ).
- Per-jurisdiction fee schedules possible (regulatory cost differences).
- JurisdictionPort (Phase 14) integration for jurisdiction validation.

### HUMAN-APPROVED

Contracts are Business/Legal decisions per Phase 1 rule 5; require Legal Counsel + CFO signatures.
**Linter rule 214:** contracts require HUMAN-APPROVED signature (Legal Counsel + CFO; Phase 1 rule 5).

## Alternatives

- **Single jurisdiction per contract** (rejected). Operators are multi-jurisdiction; single jurisdiction forces multiple contracts per operator.
- **No versioning** (rejected). Billing cannot determine historical fee schedule. The GAN/Tabcorp dispute is the canonical example.
- **Mutable contracts** (rejected). Audit trail destroyed; legal risk.
- **No lifecycle FSM** (rejected). Status transitions ungoverned; suspended contracts continue billing.
- **Email amendments** (rejected). The GAN/Tabcorp dispute showed email amendments are unenforceable without version history.
- **No jurisdiction scope** (rejected). Per-jurisdiction fee schedules impossible; regulatory cost differences unhandled.

## Consequences

- Contract + ContractVersion models.
- Lifecycle FSM (5 states; audited transitions).
- Multi-jurisdiction scope.
- 7+ year retention (Phase 9).
- HUMAN-APPROVED (Legal Counsel + CFO; linter rule 214).
- Billing uses version effective at billing period (not current).

## Validation Plan

- **Contract creation test:** create contract; assert HUMAN-APPROVED signature required; assert status=draft.
- **Versioning test:** amend contract; assert new ContractVersion created; assert old version retained; assert `effective_until` set on old version.
- **FSM transition tests:** draft→active (signed); active→suspended (breach); suspended→active (resolved); active→terminated (ended); active→expired (end_date).
- **Multi-jurisdiction test:** contract with UK + MGA + NJ; assert per-jurisdiction fee schedules applied.
- **Retention test:** attempt to delete contract <7 years old; assert rejected.
- **Billing period version test:** billing for period 2026-06; assert uses ContractVersion effective on 2026-06-01 (not current version).
