# ADR-0028 — Scanning stack (gitleaks secret scan + pip-audit dep scan)

## Context

Phase 4 hardens CI with secret and dependency scanning. Secret leaks via committed credentials are a top industry incident cause. Known-vulnerable dependencies (CVEs) are exploitable. Both must be scanned automatically.

## Decision

Adopt gitleaks for secret scanning: pre-commit hook + CI push-diff + weekly full scan. .gitleaks-baseline.json records known findings (scan-forward, no history rewrite; rotation = open question Q40). Adopt pip-audit for dependency scanning: on-push + daily. CVSS ≥7.0 blocks the build. .pip-audit-allowlist.txt records false positives with owner + due date. Both run in CI and nightly.

## Alternatives

Alternatives: (a) trufflehog — alternative secret scanner; (b) Snyk — commercial dep scanning; (c) GitHub native secret scanning — requires GitHub Advanced Security (paid). (a) rejected for overlapping coverage (gitleaks is FOSS standard); (b) rejected for cost (Q5-blocked); (c) rejected for paid tier.

## Consequences

gitleaks baseline must be maintained as new secrets are found. pip-audit allowlist must be reviewed monthly (stale allowlists are a common audit finding). CVSS threshold (7.0) is a judgment call; may need tuning. Scan runtime adds to CI minutes (Q37 ASSUMED).

## Validation Plan

Phase 4: scans clean or baseline/allowlist-justified. Phase 4: weekly full gitleaks scan scheduled. Phase 4: daily pip-audit scheduled. Phase 5: review allowlists monthly.
