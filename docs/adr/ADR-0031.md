# ADR-0031 — AuthN strategy (JWT JWS + rotating refresh + Argon2id + MFA TOTP + API keys + service JWTs)

## Context

Phase 6 introduces authentication for human users, partner integrations, and service accounts. The strategy must cover: password hashing (Argon2id), JWT access tokens (JWS), rotating refresh tokens with Redis blacklist, MFA (TOTP + recovery codes), login throttling + lockout, API key authN for partners, and service-account JWTs with typ=service claim. The strategy must compose with the Phase 5 tenant middleware (ADR-0029) and the Phase 4 error format (ADR-0026).

## Decision

Adopt JWT (JWS, HS256 for Phase 6 stub; RS256 in Phase 7 with key rotation) for access tokens (15min lifetime). Refresh tokens rotate on every use (30d lifetime); old tokens blacklisted in Redis (refresh_token_blacklist table for durable record). Passwords hashed with Argon2id (params from env: time_cost=3, memory_cost=64MB, parallelism=4). MFA: TOTP (RFC 6238) + 10 recovery codes (hashed). Login throttling: 5 failures → 15min lockout (Redis). API keys: hashed in DB, constant-time comparison. Service JWTs: typ=service claim, no refresh token, short lifetime (1h).

## Alternatives

Alternatives: (a) session-based auth (Django sessions) — CSRF + state burden; (b) opaque tokens (no JWT) — requires DB lookup per request; (c) Bcrypt instead of Argon2id — less modern; (d) WebAuthn for MFA — Phase 7+ (Q43 scope). (a) rejected for state; (b) rejected for DB overhead; (c) rejected for modernity; (d) deferred.

## Consequences

JWT signing key management is critical (rotation, revocation). Refresh token blacklisted in Redis must be TTL'd to avoid unbounded growth. MFA recovery codes must be hashed (not plaintext). Login throttling can be abused for DoS (attacker locks out a user); mitigated by lockout keyed on username+IP, not username alone. SMS-based MFA is out of scope (Q44 blocked).

## Validation Plan

Phase 6: login + refresh + logout endpoints return Phase 4 error format. Phase 6: MFA flow test (setup, verify, recovery). Phase 6: refresh rotation test (old token blacklisted). Phase 6: login throttling test (5 failures → lockout). Phase 7: RS256 + key rotation. Phase 7: load-test JWT verification.
