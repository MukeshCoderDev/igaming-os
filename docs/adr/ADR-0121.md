# ADR-0121 — LLM Evaluation Suite (Regression, Injection, Hallucination, Citation, Truth)

## Context

LLMs are probabilistic. Unlike traditional software where the same input always produces the same output, LLMs produce different outputs for the same input across runs, model versions, and temperature settings. Without a continuous evaluation suite, you cannot detect:
- **Regression:** a prompt or model change degrades response quality.
- **Injection vulnerability:** a new prompt template is vulnerable to prompt injection.
- **Hallucination:** a model upgrade increases the hallucination rate from 1% to 5%.
- **Citation inaccuracy:** a retrieval change causes citations to point to wrong chunks.
- **Truth contradiction:** a SQL schema change breaks the TruthConsistencyValidator.

The 2024 Apple Intelligence incident illustrates the stakes: Apple shipped an AI summarization feature that hallucinated news headlines; BBC reported the inaccuracies; Apple pulled the feature. Apple did not have a continuous eval suite that caught the hallucination before production. The fix was retroactive (pull the feature); the cost was reputational damage.

Phase 19 mandates a 5-type eval suite that runs continuously in CI: regression, injection, hallucination, citation, truth. Every model/prompt change triggers the eval suite; nightly full eval catches drift.

## Decision

### Eval suite (5 types)

**1. Regression evals:**
- Golden datasets per query type (chat, RAG, agent tool).
- Per tenant; per jurisdiction.
- Metrics: precision, recall, F1, response quality score (human-rated on a 1-5 scale; subset evaluated).
- Run on every model/prompt change (CI gate).
- Target: no regression >5% on any metric.

**2. Injection evals:**
- Prompt injection attacks (system prompt override, instruction injection in user query).
- Jailbreak attempts (DAN, role-play bypass, hypothetical framing).
- All must be rejected (hard fail if any succeeds).
- Run continuously in CI; nightly full injection suite.
- Target: 100% rejection rate.

**3. Hallucination evals:**
- Ungrounded claims (claim not supported by retrieved chunks).
- Fabricated facts (claim contradicts SQL facts).
- Hallucinated citations (citation not in retrieved set — caught by ADR-0119 Citation Builder).
- Metrics: hallucination rate; target <1%.
- Run nightly; on every model/prompt change.

**4. Citation accuracy evals:**
- Grounded claims cite correct chunks (verified by human annotators on a subset).
- Citation precision/recall.
- Target: >95% accuracy.
- Run nightly; on every retrieval change.

**5. Truth consistency evals:**
- Claims referencing facts validated against SQL (TruthConsistencyValidator, ADR-0120).
- Contradiction rate; target: 0%.
- Safe fallback triggered correctly on contradiction.
- Run nightly; on every SQL schema change.

### Property-based tests

- Hypothesis-based; generate edge cases (unusual queries, malformed input, adversarial patterns).
- Run on every commit; nightly full property-based suite.

### Continuous evaluation

- CI: eval suite runs on every model/prompt change (regression + injection subsets).
- Nightly: full eval suite (all 5 types + property-based).
- Dashboard: metrics tracked over time; trend lines; alert on regression.
- Alert: any metric below target → Slack `#ai-alerts` + block merge.

## Alternatives

- **Manual evals** (rejected). Cannot scale; subjective; slow.
- **No evals** (rejected). LLM regression undetectable. The Apple Intelligence incident is the canonical example.
- **Regression only (no injection/hallucination/citation/truth)** (rejected). Each eval type catches a different defect; omitting any leaves a blind spot.
- **Evals on release only (not continuous)** (rejected). Drift between releases is undetected; the nightly suite catches gradual degradation.
- **Human evals only (no automated metrics)** (rejected). Slow; expensive; cannot run in CI.
- **Automated metrics only (no human evals)** (rejected). Automated metrics miss nuance; human subset eval catches quality issues that metrics miss.

## Consequences

- 5-type eval suite required (regression, injection, hallucination, citation, truth).
- Golden datasets per query type per tenant per jurisdiction.
- Continuous CI integration (every model/prompt change).
- Nightly full eval suite.
- Metrics tracked on dashboard; alert on regression.
- Property-based tests (Hypothesis).
- Human subset eval (response quality on 1-5 scale).
- Target metrics: regression <5%, injection 100% rejection, hallucination <1%, citation >95%, truth 0% contradiction.

## Validation Plan

- **Regression eval test:** run regression suite on a known-good model; assert metrics within target.
- **Injection eval test:** run injection suite; assert 100% rejection.
- **Hallucination eval test:** run hallucination suite; assert rate <1%.
- **Citation accuracy eval test:** run citation suite; assert accuracy >95%.
- **Truth consistency eval test:** run truth suite; assert contradiction rate 0%.
- **CI integration test:** make a model change; assert CI runs eval suite; assert merge blocked if metrics below target.
- **Nightly full eval test:** trigger nightly suite; assert all 5 types run; assert dashboard updated.
- **Property-based test:** run Hypothesis suite; assert edge cases handled.
- **Alert test:** metric below target → Slack alert + merge blocked.
