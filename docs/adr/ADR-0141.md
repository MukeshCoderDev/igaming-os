# ADR-0141 — Campaign Negative Test Suite (Suppressed, Excluded, Cooling-Off, Caps, Consent)

## Context

The bolded acceptance criterion ("campaign never queues to suppressed, excluded, or cooling-off players; caps enforced at send time") is the most consequential marketing integrity test. Without a comprehensive negative test suite, the Suppression Drift pain (blueprint §3) is unverifiable.

The 2022 UK GC enforcement (£3M, cited in ADR-0137) was partly a testing failure: the operator had positive tests ("does the campaign send to eligible players?") but no negative tests ("does the campaign NOT send to suppressed players?"). The suppression bug went undetected because no test verified the negative case. The regulator called it "systemic testing deficiency" — not because the code was wrong, but because the tests did not verify the invariant.

Phase 22's negative test suite is the architectural mitigation: 5 categories, 18 tests, covering every way a campaign should NOT send. The comprehensive mixed-segment test (eligible + suppressed + excluded + cooling-off players in one campaign) is the acceptance criterion — it verifies that only eligible players are queued, others denied with correct reasons, audit events for all denials, journey continues for eligible players.

## Decision

### Campaign negative test suite (5 categories, 18 tests)

#### 1. Suppressed Player Tests (5 tests)

- **Test 1:** suppressed player (unsubscribed) → campaign queue denied → `E_MARKETING_GATE_DENIED` (reason=suppressed).
- **Test 2:** suppressed player (hard bounce) → denied.
- **Test 3:** suppressed player (complaint) → denied.
- **Test 4:** player unsubscribes mid-journey → next step denied → enrollment exits (exit_reason=unsubscribed).
- **Test 5:** DSAR-erased player → not in segment (RGPort prefiltering) → not queued.

#### 2. Excluded Player Tests (3 tests — Law 18)

- **Test 6:** self-excluded player → campaign queue denied → `E_MARKETING_GATE_DENIED` (reason=excluded).
- **Test 7:** player self-excludes mid-journey (kill-switch) → next step denied → enrollment exits (exit_reason=self_excluded).
- **Test 8:** player self-excludes between queue-time and send-time → send denied (deterministic join catches real-time).

#### 3. Cooling-Off Player Tests (3 tests — Law 18)

- **Test 9:** cooling-off player → campaign queue denied → `E_MARKETING_GATE_DENIED` (reason=cooling_off).
- **Test 10:** player enters cooling-off mid-journey → next step denied → enrollment exits (exit_reason=cooling_off).
- **Test 11:** player exits cooling-off → re-enrolled in segment → eligible for campaigns.

#### 4. Cap Enforcement Tests (4 tests — Law 24)

- **Test 12:** recipient daily cap exceeded → send denied → `E_MARKETING_GATE_DENIED` (reason=cap_exceeded).
- **Test 13:** tenant monthly cap exceeded → send denied.
- **Test 14:** channel cap exceeded (email cap met; SMS still allowed) → email denied, SMS allowed.
- **Test 15:** cap reset (daily reset) → send allowed again.

#### 5. Consent Tests (3 tests — Phase 9)

- **Test 16:** player without consent for (purpose, channel) → send denied → `E_MARKETING_GATE_DENIED` (reason=no_consent).
- **Test 17:** player revokes consent mid-journey → next step denied → enrollment exits (exit_reason=no_consent).
- **Test 18:** player consents mid-journey → re-enrolled → eligible.

### Comprehensive Negative Test (Acceptance Criterion)

- **Test 19 (comprehensive mixed-segment):** campaign with mixed segment (eligible + suppressed + excluded + cooling-off players).
  - Verify: only eligible players queued; others denied with correct reasons.
  - Verify: audit events for all denials.
  - Verify: journey continues for eligible players.

### CI enforcement

- All 19 tests run in CI on every commit touching engagement module.
- Any test failure blocks merge.
- Nightly full suite run (catches drift).
- Test results dashboard (pass/fail per test; trend over time).

## Alternatives

- **Positive tests only** (rejected). The acceptance criterion is a negative test ("never queues to..."). The 2022 UK GC incident showed positive-only testing misses suppression bugs.
- **Manual testing** (rejected). Cannot scale; cannot verify in CI; subjective.
- **Fewer categories** (rejected). Each category tests a distinct invariant (suppression, exclusion, cooling-off, caps, consent); omitting any leaves a blind spot.
- **No comprehensive mixed-segment test** (rejected). Individual category tests verify each invariant in isolation; the mixed-segment test verifies they work together (a player who is both suppressed AND excluded is denied once, not twice; audit event records one reason).
- **No CI enforcement** (rejected). Tests that don't run in CI are tests that drift; the nightly suite catches gradual degradation.
- **No audit event verification** (rejected). Law 9; regulator inquiry requires "prove the denial was logged."

## Consequences

- 5-category negative test suite (18 tests + 1 comprehensive).
- CI-enforced (every commit; nightly full suite).
- Test results dashboard.
- The 2022 UK GC testing deficiency is cured.
- The Suppression Drift pain is verifiable (Test 5: DSAR-erased player not queued; Test 8: self-exclude between queue and send → denied).
- The acceptance criterion ("campaign never queues to suppressed, excluded, or cooling-off players; caps enforced at send time") is verified by Tests 1-15 + Test 19.

## Validation Plan

- **Suppressed player tests (Tests 1-5):** each test sets up the suppression scenario; triggers campaign; asserts denial with correct reason.
- **Excluded player tests (Tests 6-8):** each test sets up self-exclusion; triggers campaign; asserts denial; Test 8 verifies deterministic join (self-exclude between queue and send).
- **Cooling-off player tests (Tests 9-11):** each test sets up cooling-off; asserts denial; Test 11 verifies re-enrollment after cooling-off exits.
- **Cap enforcement tests (Tests 12-15):** each test sets up cap scenario; asserts denial; Test 14 verifies channel-specific caps; Test 15 verifies cap reset.
- **Consent tests (Tests 16-18):** each test sets up consent scenario; asserts denial; Test 18 verifies re-enrollment after consent.
- **Comprehensive mixed-segment test (Test 19):** campaign with 4 player types; assert only eligible queued; assert audit events for all denials; assert journey continues for eligible.
- **CI integration test:** commit engagement code; assert all 19 tests run; assert merge blocked on failure.
- **Audit event verification:** for each denial test, assert `marketing.gate_decision` audit event with correct reason + player_uuid + correlation_id.
