# ADR-0011 — Immutable ledger entries (no update, no delete)

## Context

A financial ledger that allows updates or deletes cannot be audited. Corrections must be visible as corrections, not as silent overwrites. This is foundational to the platform's regulatory posture (FATF, BSA).

## Decision

Ledger entries are immutable. Corrections are made by posting compensating entries that reference the original. The net balance is the sum of all entries, including corrections. There is no update and no delete API on the ledger.

## Alternatives

Alternatives considered: (a) updatable ledger with audit trigger — corrections invisible in the balance; (b) updatable ledger with correction markers — fragile; (c) append-only with hard deletes by admin — invites abuse. (a) and (b) rejected for auditability; (c) rejected for tamper risk.

## Consequences

Storage cost grows monotonically. Balance computation is O(N) in entries; materialized balances (DEC-0018 read models) mitigate. Reversal of an erroneous entry requires a compensating entry, which inflates gross volume metrics.

## Validation Plan

Phase 11: implement; verify that compensating entries produce the same net balance as a deletion would. Phase 11: load-test balance computation at 10k entries. Phase 12+: verify that customer deposits compose with immutable entries.
