# ADR-0124 — Anchored RAG Pipeline (10 Steps; Integrated End-to-End)

## Context

The 10-step Anchored RAG Pipeline (blueprint §6) is the most complex single subsystem in Noventra OS. It integrates Laws 11, 12, 13, 2, 16, 6, and 22. Each step is a separate concern; the integration is the challenge. A single weak step breaks the entire pipeline.

The threat is existential. An AI that writes ledger entries (Law 11 violation) destroys financial integrity. An AI that names hallucinated citations (Law 12 violation) destroys trust. An AI that contradicts SQL facts (Law 13 violation) destroys both. An AI that retrieves cross-tenant chunks (Law 2 violation) destroys privacy. An AI that fails silently on distress signals (Law 16 violation) destroys player protection. An AI that touches Process Truth (Law 6 violation) destroys the bifurcated truth that the entire financial layer depends on.

The 2024 Air Canada chatbot incident (cited in ADR-0116, ADR-0120) is the canonical example of what happens when the pipeline is not anchored: the chatbot gave incorrect information, the customer acted on it, and the airline was held liable. The Anchored RAG Pipeline is the architectural mitigation: 10 steps, each with a specific law to enforce, each as a pure function, each independently testable, each composed into a pipeline that produces verified, grounded, consistent, cited, safe responses.

## Decision

### 10-step pipeline (per blueprint §6)

**Step 1: Unified Router**
- Deterministic regex first (FAQ, simple lookups — "what is the bonus wagering requirement?" → FAQ lookup).
- LLM last (complex queries — "how do I claim my bonus if I deposited via crypto?" → RAG).
- **Distress short-circuits ALL (Law 16):** distress signals (self-exclusion trigger, reality check failure, RG distress) bypass AI entirely; deterministic response via Phase 14 RGPort integration (<50ms; no LLM call).
- Linter rule 174: distress signals bypass AI entirely.

**Step 2: Retrieval Planner**
- Persona context (player, operator admin, support agent — different retrieval strategies).
- Tenant context (`tenant_id` — mandatory for Law 2 prefiltering).
- Language context (player's language — mandatory for Law 2 prefiltering).
- Output: retrieval plan (query type, persona, tenant, language, jurisdiction).

**Step 3: Prefiltered Hybrid Retrieval (ADR-0118)**
- pgvector (semantic similarity) + FTS (keyword match).
- **Prefiltered by `tenant_id` + `jurisdiction` + `language` + `lifecycle = 'active'` (Law 2).**
- Hybrid scoring: weighted combination (0.7 semantic + 0.3 FTS; configurable).
- Linter rules 165, 166, 167 enforce prefiltering.

**Step 4: Ingestion Sandbox**
- All chunk fields wrapped in `<evidence trusted="false">` tags.
- LLM treats retrieved content as untrusted data (never as instructions).
- Prevents prompt injection from retrieved chunks (a chunk containing "ignore previous instructions" is treated as evidence, not as an instruction).
- Linter rule: all retrieved chunks must be wrapped in `<evidence trusted="false">` before LLM input.

**Step 5: LLM Answer Composer**
- Outputs claims (structured: `{claim_id, claim_text, fact_references}`).
- **EXPLICITLY FORBIDDEN from naming citations (Law 12).**
- Prompt instructs: "Output claims only; do not cite sources; do not reference chunk IDs; do not say 'according to...'."
- Linter rules 168, 169 enforce LLM citation prohibition.

**Step 6: Claim-Level Grounder (ADR-0119)**
- NLI (Natural Language Inference) or span mapping: does this claim exist in the evidence?
- Maps each claim to retrieved chunk IDs.
- Ungrounded claims (no supporting chunk) flagged for hard fail.

**Step 7: Truth Consistency Validator (ADR-0120)**
- **Checks fact-referencing claims against SQL facts (Law 13).**
- 6 fact types: balance, payment, KYC, RG, bonus, round.
- **Contradiction = hard fail; safe fallback; incident signal.**
- Linter rules 172, 173 enforce truth validation + hard fail.

**Step 8: Output Guardrails**
- Injection scan (detect injected instructions in output).
- PII leak scan (no PII in response — player queries are PII; response must not leak other players' PII).
- Tone check (no harmful content; no gambling advice; no encouragement of excessive play).
- Schema validation (response conforms to expected schema — claims array, citations array, metadata).

**Step 9: Machine-Assembled Citation Builder (ADR-0119)**
- **Attaches real chunk IDs to grounded claims (Law 12).**
- Verifies chunk IDs exist in retrieved set (hard validation).
- Ungrounded claims: no citation; flagged; hard fail if critical.

**Step 10: Safe Renderer**
- **Injects SQL facts as placeholders (amounts, dates, IDs — never machine-translated).**
- Translates prose only (Law 15 — Mother Tongue; the LLM translates the prose; SQL facts are injected as immutable placeholders).
- Example: "Your balance is {{balance}}" → "Your balance is $750.00" (the $750.00 is injected from SQL; the prose "Your balance is" is LLM-translated).
- Prevents the LLM from mistranslating numbers, dates, or IDs.

### Pipeline composition

Each step is a pure function: input → output, no side effects, deterministic (except Step 5 which calls the LLM — but the LLM call is through the gateway which handles non-determinism). Steps are composed in sequence; each step's output is the next step's input. Any step can hard-fail the pipeline; hard fail → safe fallback ("I cannot answer this; please contact support.").

### Latency targets

- **End-to-end RAG query:** <5s p99 (10-step pipeline).
- Step 1 (Router): <50ms p99 (regex + distress check).
- Step 3 (Retrieval): <500ms p99 (pgvector + FTS).
- Step 5 (LLM): <2s p99 (provider-dependent).
- Step 7 (Truth validation): <200ms p99 (parallel SQL queries).
- Step 9 (Citation assembly): <100ms p99.
- Distress short-circuit (Step 1 bypass): <50ms p99.

## Alternatives

- **Fewer steps (collapse steps)** (rejected). Each step enforces a specific law; collapsing steps conflates concerns and makes testing impossible.
- **More steps (over-engineer)** (rejected). 10 steps is the blueprint mandate; adding more adds latency without value.
- **Async pipeline (steps run in parallel)** (rejected). Steps are sequential by design (Step 6 needs Step 5's output; Step 9 needs Step 6's output). Parallelism within a step (e.g., Step 7 parallel SQL queries) is fine.
- **No safe fallback (let failures propagate)** (rejected). Player sees a 500 error; abandons the platform. Safe fallback is the Law 16 mandate.
- **LLM translates SQL facts** (rejected). LLM mistranslation of numbers/dates/IDs is a financial integrity defect. SQL facts are immutable placeholders.
- **No distress short-circuit** (rejected). Law 16 mandates distress bypasses AI. An LLM generating a "sympathetic response" to a self-exclusion signal is a regulator-reportable defect.

## Consequences

- 10-step pipeline implemented as 10 pure functions.
- Each step independently testable.
- Any step can hard-fail → safe fallback.
- Distress short-circuit (Step 1 bypass; <50ms).
- Latency target: <5s p99 end-to-end.
- Linter rules 165-175 enforce the pipeline invariants.
- The pipeline is the heart of Phase 19; failure here is existential.
- Q5-blocked for real LLM provider adapters; stub for dev.

## Validation Plan

- **End-to-end pipeline test:** submit a RAG query; assert all 10 steps execute; assert response has claims + citations + no contradictions.
- **Distress short-circuit test:** submit a distress signal; assert Step 1 bypasses AI; assert deterministic response <50ms.
- **Injection suite (5 types):**
  - Prompt injection (system prompt override; instruction injection) → blocked by Step 4 Ingestion Sandbox.
  - Jailbreak (DAN, role-play bypass) → blocked by Step 8 Output Guardrails.
  - RAG poisoning (malicious chunks) → blocked by Step 4 + Step 8.
  - Citation hallucination (LLM names citations) → blocked by Step 5 prohibition (linter rules 168-169).
  - Truth contradiction (AI contradicts SQL) → blocked by Step 7 TruthConsistencyValidator (hard fail).
- **Retrieval isolation test (Law 2):** tenant A query returns zero tenant B chunks.
- **Synchronous revocation test (Law 10):** revoke a chunk; query; assert chunk not returned (same transaction).
- **Machine-assembled citation test (Law 12):** assert all citations are machine-assembled; assert LLM never names citations.
- **TruthConsistencyValidator hard-fail test (Law 13):** contradicting claim → hard fail → safe fallback.
- **AI-never-writes-to-domain-truth test (Law 11):** linter rule 175; grep for LLM output → domain table write; assert zero.
- **Degradation L0-L4 test (Law 16):** trigger each level; assert correct behavior.
- **Latency test:** 10-step pipeline <5s p99; distress short-circuit <50ms p99.
- **Linter rules 165-175 test:** each rule verified independently.
