# ADR-0115 — LLM Gateway — Provider Abstraction, Routing, Rate Limiting, Cost & Degradation

## Context

Phase 19 introduces LLM integration. LLMs are untrusted (Law 11 — AI Boundary). The gateway is the single chokepoint through which every LLM call must pass; it abstracts providers, controls costs, and degrades gracefully (Law 16 — Voice & Degradation). Vendor selection is Q5-blocked (OQ-AI-001).

The threat model is operational, not regulatory, but the consequences are existential. Without a gateway:
- A misconfigured client calls OpenAI directly with no cost tracking → a single runaway loop costs $50K+ in a weekend (this happened to a fintech in 2024; the engineer forgot to cap retries).
- A provider outage with no fallback → the entire AI layer goes dark; players see "AI unavailable" instead of a deterministic response.
- A distress signal (player self-exclusion, reality check failure) reaches the AI → the LLM generates a sympathetic response instead of triggering the regulator-mandated deterministic short-circuit.

Law 16 mandates L0→L4 degradation: the system degrades gracefully but never abandons the user. Distress signals bypass AI entirely (deterministic response via Phase 14 RGPort integration). This is not optional — it is the law.

## Decision

### LLMGateway service

- **Provider abstraction:** `LLMProviderPort` interface; adapters for OpenAI, Anthropic, Google, local (Ollama); `StubLLMAdapter` for dev (Q5-blocked for real providers).
- **Routing:** model selection per query type (chat, RAG, agent tool); configurable per tenant.
- **Rate limiting:** per tenant, per user, per prompt type; Redis-based (token bucket).
- **Cost tracking:** per request (tokens × rate); per tenant aggregation; per prompt version.
- **Token counting:** input + output; budget enforcement before + after call.
- **Retry strategy:** exponential backoff (1s, 2s, 4s, max 3 retries); fallback model on provider failure.
- **Degradation (Law 16):** L0 (full AI) → L1 (cached responses) → L2 (template responses) → L3 (deterministic fallback) → L4 (refuse + log).
- **Distress short-circuit (Law 16):** distress signals from Phase 14 RGPort bypass AI entirely; deterministic response (<50ms; no LLM call).

### Budget enforcement

- Per-tenant monthly budget (configurable; OQ-AI-005 default).
- Hard cutoff when exceeded (degrade to L3 — deterministic fallback).
- Alert at 80% threshold (Slack `#ops-alerts` + email to CFO).
- Budget reset monthly (UTC midnight on the 1st).

### Degradation levels (Law 16)

| Level | Behavior | Trigger |
|---|---|---|
| L0 | Full AI (LLM call) | Normal operation |
| L1 | Cached responses (semantic cache hit) | Cache hit OR LLM latency >2s |
| L2 | Template responses (pre-written) | LLM unavailable OR cost >80% budget |
| L3 | Deterministic fallback (regex/FAQ) | Cost >100% budget OR provider outage |
| L4 | Refuse + log ("AI unavailable; please contact support") | All fallbacks failed |

## Alternatives

- **Direct provider calls** (rejected). Vendor lock-in; no cost control; no degradation; the 2024 fintec incident is the canonical example.
- **No degradation** (rejected). Law 16 mandates graceful degradation. Silent failure abandons the user.
- **Single provider (no abstraction)** (rejected). Vendor lock-in; provider outage = platform outage.
- **No distress short-circuit** (rejected). Law 16 mandates distress bypasses AI. An LLM generating a "sympathetic response" to a self-exclusion signal is a regulator-reportable defect.
- **Cost tracking without budget enforcement** (rejected). Tracking without cutoff allows cost explosion.
- **Soft cutoff (warn but continue)** (rejected). Costs still explode; the warn is ignored under operational pressure.

## Consequences

- Provider abstraction required (`LLMProviderPort` + adapters).
- Budget enforcement required (hard cutoff at 100%).
- Degradation L0-L4 implemented; distress short-circuit mandatory.
- Every LLM call goes through the gateway (linter rule 159 — no direct provider calls).
- Every LLM call records cost (linter rule 161 — `LLMCostRecord` created).
- Q5-blocked for real provider adapters; stub for dev.
- Open question OQ-AI-001: LLM provider selection (Q5-blocked).
- Open question OQ-AI-005: per-tenant monthly budget default (OPEN).
- Open question OQ-AI-006: degradation L0-L4 thresholds (OPEN).

## Validation Plan

- **Provider routing test:** route a chat query to chat model; a RAG query to RAG model; assert correct model selected.
- **Rate limiting test:** exceed per-tenant rate limit; assert 429 response.
- **Cost tracking test:** make an LLM call; assert `LLMCostRecord` created with correct tokens + cost.
- **Degradation L0→L4 test:** trigger each level (normal → cache hit → template → deterministic → refuse); assert correct behavior.
- **Distress short-circuit test:** send a distress signal (SE activation); assert AI bypassed; assert deterministic response <50ms.
- **Budget cutoff test:** exceed 100% budget; assert L3 degradation; assert no further LLM calls.
- **Budget alert test:** exceed 80% budget; assert Slack + email alert.
- **Linter rule 159 test:** grep for direct provider API calls (openai.ChatCompletion.create, anthropic.Anthropic().completions.create); assert zero matches outside gateway.
- **Linter rule 161 test:** grep for LLM call code; assert each creates `LLMCostRecord`.
