# ADR-0133 — Periodic Compliance Reviews — Cadence, Findings & Remediation

## Context

Periodic reviews are regulator-mandated. Internal audit annual; external audit annual; regulator inspection ad-hoc; self-assessment quarterly. Findings require remediation tracking — a finding without remediation is an audit failure.

The 2023 Casino Royale enforcement action (£2M fine) illustrated the cost of untracked findings: the operator's external audit identified 14 control deficiencies, but the compliance team tracked them in email threads. When the regulator followed up 6 months later, 9 of 14 findings had no evidence of remediation; the email threads were lost, forwarded, or forgotten. The regulator called it "systemic remediation failure" — not because the findings weren't identified, but because they weren't tracked to closure.

Phase 21's review framework is the architectural mitigation: every review creates findings; every finding has an owner, due date, and remediation status; overdue findings escalate; critical findings alert executives immediately. The remediation evidence (proof that the finding was fixed) is stored in the EvidenceRepository (ADR-0132).

### Findings tracking

Each finding in the `findings` JSONB has:
- `finding_id` UUID
- `severity` enum (critical, high, medium, low)
- `description` TEXT
- `owner` str (named human; responsible for remediation)
- `due_date` date
- `remediation_status` enum (open, in_progress, closed)
- `remediation_evidence_id` UUID FK → ComplianceEvidence (nullable; proof of remediation)
- `created_at` datetime

**Linter rule 195:** every compliance review finding has `owner` + `due_date` + `remediation_status`.

### Remediation workflow

1. **Finding created:** during review, finding added to `findings` JSONB; `remediation_status=open`.
2. **Owner assigned:** `owner` field set (named human); owner notified (Slack/email).
3. **Remediation task created:** owner creates remediation task; `remediation_status=in_progress`.
4. **Owner remediates:** owner fixes the control; collects evidence; attaches `remediation_evidence_id` (EvidenceRepository ADR-0132).
5. **Finding closed:** `remediation_status=closed`; evidence verified by compliance officer.
6. **Overdue findings:** `due_date` passed + `remediation_status != closed` → escalation to compliance officer; alert.
7. **Critical findings:** `severity=critical` → immediate alert + executive notification (CFO + CTO + Compliance Officer).

### Escalation

- **Overdue:** daily Celery task `check_finding_overdue`; findings past `due_date` + not closed → escalate.
- **Critical:** on creation, immediate alert (PagerDuty to compliance officer; email to CFO + CTO).
- **Repeated findings:** same finding in 2+ consecutive reviews → escalate to external auditor (systemic issue).

## Alternatives

- **No reviews** (rejected). Regulator-mandated; unreviewed controls drift.
- **No findings tracking** (rejected). Findings without remediation = audit failure. The Casino Royale incident is the canonical example.
- **Email-based tracking** (rejected). Lost; forwarded; forgotten. The Casino Royale incident used email.
- **No severity classification** (rejected). All findings treated the same → critical issues lost in noise.
- **No escalation** (rejected). Overdue findings sit forever; critical findings unnoticed.
- **No remediation evidence** (rejected). "We fixed it" without proof = unverified closure; regulator rejects.
- **No repeated-finding detection** (rejected). Systemic issues (same finding repeatedly) go unflagged.

## Consequences

- ComplianceReview model with 4 review types.
- Findings tracking (JSONB with owner + due_date + remediation_status).
- Remediation workflow (create → assign → remediate → close with evidence).
- Escalation (overdue + critical + repeated).
- Linter rule 195: every finding has owner + due_date + remediation_status.
- Remediation evidence linked to EvidenceRepository (ADR-0132).

## Validation Plan

- **Review scheduling test:** schedule internal_audit; assert Celery beat triggers; assert review created.
- **Findings tracking test:** create review with 3 findings; assert each has owner + due_date + remediation_status.
- **Remediation workflow test:** finding open → assign → remediate → attach evidence → close; assert status transitions; assert evidence linked.
- **Overdue escalation test:** finding past due_date + not closed; assert escalation alert.
- **Critical finding alert test:** create critical finding; assert immediate alert (PagerDuty + email to CFO/CTO).
- **Repeated finding detection test:** same finding in 2 reviews; assert escalation to external auditor.
- **Linter rule 195 test:** grep for findings; assert each has owner + due_date + remediation_status.
