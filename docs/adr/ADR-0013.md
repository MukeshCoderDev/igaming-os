# ADR-0013 — Multi-currency via ISO 4217

## Context

Currency codes must be standardized for interoperability with external systems (banks, payment networks, reporting). Ad-hoc codes invite ambiguity and integration bugs.

## Decision

All currencies are identified by ISO 4217 three-letter codes. The platform maintains a currency registry with metadata (precision, symbol, rounding convention). Custom currencies are forbidden. The registry is versioned; updates follow ISO 4217 amendments.

## Alternatives

Alternatives considered: (a) ad-hoc codes — ambiguity; (b) ISO 4217 numeric codes — less readable; (c) custom registry with ISO aliases — complexity. (a) rejected for ambiguity; (b) rejected for readability; (c) rejected for complexity.

## Consequences

ISO 4217 updates require registry versioning and migration. Historical transactions must retain the currency metadata that was in effect at transaction time (e.g., precision changes for currency redenominations).

## Validation Plan

Phase 11: implement the registry; verify that all ISO 4217 currencies are present. Phase 11: integration test with a payment API; verify currency code interop. Phase 11: redenomination test (simulate a currency precision change).
