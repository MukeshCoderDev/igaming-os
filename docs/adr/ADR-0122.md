# ADR-0122 — Cost Accounting (Per-Request, Per-Tenant, Budget Enforcement)

## Context

LLM costs are variable and can explode. Unlike fixed infrastructure costs (servers, databases), LLM costs scale with usage — every token costs money, and a single runaway loop or a high-traffic tenant can generate $50K+ in costs over a weekend. The 2024 fintech incident (cited in ADR-0115) is the canonical example: an engineer forgot to cap retries, a provider had a transient error, and the retry loop generated $47K in OpenAI costs in 14 hours.

The B2B model requires per-tenant cost allocation: each tenant pays for their LLM usage. Without per-tenant cost tracking, the operator cannot chargeback; high-usage tenants subsidize low-usage tenants; the operator absorbs the cost differential. Budget enforcement prevents cost overruns: each tenant has a monthly budget; exceeding the budget degrades the AI to L3 (deterministic fallback) rather than continuing to accrue cost.

## Decision

### LLMCostRecord model

| Field | Type | Notes |
|---|---|---|
| `cost_uuid` | UUID PK | |
| `tenant_uuid` | UUID | Tenant scope (RLS) |
| `request_id` | UUID | Correlates with LLM call |
| `model` | str | e.g., `gpt-4o`, `claude-3-5-sonnet` |
| `prompt_template_uuid` | UUID FK → PromptTemplate (nullable) | |
| `input_tokens` | int | Token count (input) |
| `output_tokens` | int | Token count (output) |
| `cost_usd` | decimal(10,6) | Tokens × rate per model |
| `created_at` | datetime | auto_now_add |

**Insert-only** (Phase 7 pattern): cost records are immutable; corrections require a new record (negative amount for reversal).

### Per-request cost

- Tokens × rate per model; recorded on every LLM call (linter rule 161).
- Rate table per model (configurable; updated when providers change pricing).
- Cost computed before the call (estimate from input tokens) + after the call (actual from output tokens); the larger value is recorded (conservative billing).

### Per-tenant cost

- Aggregated monthly (`current_month_spend_usd` on `LLMTenantBudget`).
- Budget alerts at 80% (Slack + email to CFO + tenant admin).
- Hard cutoff at 100% (degrade to L3 per Law 16; no further LLM calls).
- Budget reset monthly (UTC midnight on the 1st).

### Per-prompt-version cost

- A/B testing cost comparison (which prompt version is cheaper for the same quality?).
- Cost per query type (chat vs RAG vs agent).
- Optimization: identify expensive prompts; rewrite for token efficiency.

### Budget enforcement

- Per-tenant monthly budget (configurable; OQ-AI-005 default).
- Alert at 80% threshold.
- Hard cutoff at 100% (degrade to L3 — deterministic fallback).
- Budget reset monthly.
- Grace period: 1 hour after cutoff, allow $10 overflow for in-flight requests (avoid mid-request cutoff); then hard cutoff.

### Cost allocation (chargeback)

- Monthly invoice includes LLM costs (B2B model).
- Chargeback rate: cost × 1.2 (20% markup for infrastructure overhead).
- Invoice line item: "AI Platform Usage — [month] — $X (Y tokens)".
- Tenant can view their LLM cost dashboard in real-time.

## Alternatives

- **No cost tracking** (rejected). Costs can explode; the 2024 fintec incident is the canonical example.
- **Flat-rate pricing** (rejected). Variable costs; unfair allocation; high-usage tenants subsidize low-usage.
- **Cost tracking without budget enforcement** (rejected). Tracking without cutoff allows cost explosion.
- **Soft cutoff (warn but continue)** (rejected). Costs still explode; the warn is ignored under operational pressure.
- **No chargeback (operator absorbs cost)** (rejected). B2B model requires per-tenant allocation; operator margin erodes.
- **Per-token pricing (not per-request)** (rejected). Per-token is too granular for invoicing; per-request aggregation is the industry standard.
- **No grace period (instant cutoff)** (rejected). Mid-request cutoff causes partial responses; grace period avoids this.

## Consequences

- LLMCostRecord model (insert-only; immutable).
- LLMTenantBudget model (per-tenant monthly budget + current spend).
- Budget enforcement (80% alert; 100% hard cutoff → L3).
- Monthly chargeback (cost × 1.2 markup).
- Per-prompt-version cost tracking (A/B optimization).
- Linter rule 161: every LLM call records cost (LLMCostRecord created).
- Open question OQ-AI-005: per-tenant monthly budget default (OPEN).

## Validation Plan

- **Cost tracking test:** make an LLM call; assert LLMCostRecord created with correct tokens + cost.
- **Budget alert test:** exceed 80% budget; assert Slack + email alert.
- **Hard cutoff test:** exceed 100% budget; assert L3 degradation; assert no further LLM calls.
- **Grace period test:** exceed 100% budget; assert 1-hour grace for in-flight requests; assert hard cutoff after grace.
- **Chargeback test:** generate monthly invoice; assert LLM cost line item with correct amount + markup.
- **Per-prompt-version cost test:** A/B test two prompt versions; assert cost comparison dashboard shows per-version cost.
- **Insert-only test:** attempt to UPDATE a cost record; assert DB raises.
- **Linter rule 161 test:** grep for LLM call code; assert each creates LLMCostRecord.

## Decision statement (one line)

DEC-0123 → Cost Accounting (per-request, per-tenant, per-prompt-version; budget enforcement 80% alert / 100% hard cutoff → L3; monthly chargeback with 20% markup). Owner: CFO. Status: PROPOSED.
