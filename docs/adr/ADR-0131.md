# ADR-0131 — Compliance Control Framework — Model, Framework Mapping & Testing

## Context

Compliance controls are the structured framework auditors review. Without a control registry, controls are ad-hoc and unauditable. Multiple frameworks apply simultaneously to a regulated iGaming operator: UK GC LCCP (Licence Conditions and Codes of Practice), MGA BLC (Betting and Gaming Regulations), GDPR (data protection), AML (FATF + jurisdictional AML laws), ISO 27001 (information security), SOC 2 (service organization controls).

The 2022 Star Ocean Casino enforcement action (£5M fine) illustrated the cost of ad-hoc controls: the operator's compliance team maintained controls in spreadsheets across 4 jurisdictions, with no mapping between controls and regulatory requirements. When the UK GC audited, the operator could not produce evidence that LCCP 2.1.1 (self-exclusion) was tested; the spreadsheet had been edited in place, losing the audit trail. The regulator found "systemic control deficiency" — not because the controls didn't exist, but because they were not registered, mapped, or tested in an auditable way.

Phase 21's control framework is the architectural mitigation: every control is registered, mapped to one or more regulatory requirements, owned by a named human, and tested on a schedule. Test results are immutable (Law 9); failures trigger remediation tasks; the registry is the single source of truth for "what controls exist and are they working."

## Decision

### ComplianceControl model

| Field | Type | Notes |
|---|---|---|
| `control_uuid` | UUID PK | |
| `tenant_uuid` | UUID | Tenant scope (RLS per Phase 5) |
| `control_id` | str | e.g., `AML-001`, `RG-014`, `GDPR-ART17-001` |
| `framework` | enum | ISO_27001, SOC_2, UK_GC_LCCP, MGA_BLC, GDPR, AML |
| `description` | TEXT | What the control does |
| `owner` | str | Named human (CODEOWNERS) |
| `status` | enum | active, deprecated |
| `last_reviewed_at` | datetime | |
| `last_tested_at` | datetime | |
| `test_result` | enum | pass, fail, remediation_required (nullable) |
| `created_at` | datetime | auto_now_add |
| `updated_at` | datetime | auto_now |

**Unique constraint:** `(tenant_uuid, control_id)` — no duplicate control IDs per tenant.

### Framework mapping

Each control maps to one or more regulatory requirements (per-jurisdiction). A control may satisfy requirements across multiple frameworks (e.g., `RG-014` self-exclusion satisfies UK GC LCCP 2.1.1, MGA BLC Reg 11, GDPR Art 17 (right to erasure exception)).

**ControlFrameworkMapping model:**
- `mapping_uuid` UUID PK
- `control_uuid` FK → ComplianceControl
- `framework` enum
- `requirement_ref` str (e.g., `UK GC LCCP 2.1.1`)
- `jurisdiction_code` str (nullable; null = all jurisdictions)
- `created_at` datetime

### Control testing

- **Scheduled tests:** configurable per control (default annual; some controls monthly/quarterly per regulatory mandate).
- **Test results recorded:** pass / fail / remediation_required.
- **Failures trigger remediation tasks:** finding created in ComplianceReview (ADR-0133); owner assigned; due date set.
- **Test evidence linked:** evidence stored in EvidenceRepository (ADR-0132) via `evidence_url`.
- **Linter rule 191:** every compliance control has named owner (human).

### Control ownership

- Each control has a named owner (human); owner is responsible for testing + remediation.
- Owner changes are audited (Phase 7 event `compliance.control_owner_changed`).
- Controls without an owner are a defect (linter rule 191).

## Alternatives

- **No control framework** (rejected). Regulator-mandated; ad-hoc controls unauditable. The Star Ocean Casino incident is the canonical example.
- **Single framework** (rejected). Multiple frameworks apply simultaneously; a single framework misses UK GC + MGA + GDPR + AML + ISO + SOC 2.
- **Spreadsheets** (rejected). Edited in place; no audit trail; no scheduled testing; no remediation tracking. The Star Ocean incident showed this fails.
- **No framework mapping** (rejected). Controls without mapping to requirements cannot answer "is LCCP 2.1.1 covered?" — the auditor's first question.
- **No scheduled testing** (rejected). Controls untested = controls assumed working = audit failure when they aren't.
- **No named owner** (rejected). Controls without an owner are orphaned; no one tests them; no one remediates failures.

## Consequences

- ComplianceControl model with unique constraint.
- Multi-framework mapping (ControlFrameworkMapping).
- Scheduled testing (configurable per control).
- Named owners (linter rule 191).
- Failures trigger remediation (via ComplianceReview ADR-0133).
- Test evidence linked to EvidenceRepository (ADR-0132).
- Open question OQ-COMP-001: compliance frameworks in scope (all 6? OPEN).

## Validation Plan

- **Control registry test:** register a control; assert unique constraint; assert framework mapping created.
- **Framework mapping test:** map one control to 3 frameworks; assert all 3 mappings exist; assert query "which controls satisfy LCCP 2.1.1" returns the control.
- **Scheduled test execution test:** trigger scheduled test; assert test_result recorded; assert evidence linked.
- **Failure → remediation test:** control test fails; assert finding created in ComplianceReview; assert owner assigned; assert due date set.
- **Named owner test (linter rule 191):** grep for controls without owner; assert zero matches.
- **Multi-framework coverage test:** for each framework, assert at least one control mapped; assert no regulatory requirement unmapped.
