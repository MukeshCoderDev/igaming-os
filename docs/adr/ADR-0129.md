# ADR-0129 — Retention Agent Bounds (Law 18; Excluded/Cooling-off/Caps/Bonus)

## Context

Law 18 (Law of Player Protection): Responsible gambling outranks all commercial optimization. The Retention agent (blueprint §7, Agent #9) is specifically bounded: May NOT target excluded/cooling-off players; May NOT set bonus values; May NOT queue journeys that breach frequency caps. Unbounded retention agents targeting vulnerable players are the canonical RG violation.

The 2022 UK GC enforcement action against a major operator (£3M fine) illustrates the stakes: the operator's retention marketing system sent bonus offers to self-excluded players because the suppression list was applied at send time (post-segment) but the segmentation query did not filter excluded players. A bug in the send-time filter (a missed join) caused 2,300 self-excluded players to receive bonus offers. The regulator called it a "systemic player protection failure." The fix was not better filters — it was filtering at every level (segment query + send time + tool registry).

Phase 20's Retention agent is bounded at 4 levels (defense-in-depth). No single level is sufficient; the 2022 incident showed that a single-level filter (send time only) fails when the filter has a bug. Four levels mean a bug in one level is caught by the next:

1. **Tool registry** — Retention agent's `allowed_tools` excludes protection-modifying tools.
2. **Segment query** — every segment query calls RGPort to filter excluded/cooling-off players.
3. **MarketingGate** — every journey queued goes through MarketingGate (suppression + caps + consent).
4. **Negative tests** — 4 tests verify each bound is enforced.

## Decision

### Retention agent bounds (blueprint §7 May-NOT)

1. **May NOT target excluded players** (Phase 14 SE — active self-exclusion).
2. **May NOT target cooling-off players** (Phase 14 — active cooling-off period).
3. **May NOT set bonus values** (Phase 13 — bonus values set by BonusOffer config, not agent).
4. **May NOT queue journeys that breach frequency caps** (Phase 8 MarketingGate — caps enforced at send time).

### 4-level enforcement (defense-in-depth)

#### Level 1 — Tool registry (ADR-0126)

- Retention agent's `allowed_tools` excludes player-protection-modifying tools.
- No tool to set SE; no tool to set cooling-off; no tool to set bonus values.
- `allowed_tools` for Retention agent: `segment_query`, `journey_suggest`, `draft_campaign`.
- `forbidden_tools` for Retention agent: `set_self_exclusion`, `set_cooling_off`, `set_bonus_value`, `modify_player_protection`.
- **Linter rule 179:** Retention agent's `allowed_tools` does not include protection-modifying tools.

#### Level 2 — Segment query (RGPort)

- Every segment query by Retention agent calls `RGPort.check_self_excluded` + `RGPort.check_cooling_off` for each player in the segment.
- Excluded/cooling-off players filtered out of segment before any journey is queued.
- The check is per-player (not per-segment); a player who self-excludes mid-segment-query is filtered out.
- **Linter rule 180:** Retention agent segment queries check RGPort.

#### Level 3 — MarketingGate (Phase 8 + Phase 9)

- Every journey queued by Retention agent goes through MarketingGate.
- MarketingGate checks: suppression (Phase 8 — player opted out; player excluded) + caps (Phase 8 — frequency caps per channel per player) + consent (Phase 9 — player consented to channel).
- Excluded/cooling-off players are in suppression list → denied at send time.
- Caps exceeded → denied at send time.
- Consent missing → denied at send time.
- **Linter rule 181:** Retention agent journey queues go through MarketingGate.

#### Level 4 — Negative tests

- **Test 1:** Retention agent attempts to target excluded player → denied with `E_AGENT_BOUNDARY_VIOLATION`.
- **Test 2:** Retention agent attempts to target cooling-off player → denied.
- **Test 3:** Retention agent attempts to queue journey breaching caps → denied.
- **Test 4:** Retention agent attempts to set bonus value → tool not in `allowed_tools` → denied.
- All 4 negative tests must pass (acceptance criterion for Phase 20 gate).

### Error codes

- `E_AGENT_BOUNDARY_VIOLATION` — Retention agent attempted to target excluded/cooling-off player (Level 2 or 3 denial).
- `E_AGENT_TOOL_FORBIDDEN` — Retention agent attempted to call a forbidden tool (Level 1 denial).
- `E_AGENT_CAP_BREACH` — Retention agent attempted to queue journey breaching caps (Level 3 denial).

## Alternatives

- **Single-level enforcement (tool registry only)** (rejected). Defense-in-depth required for Law 18. The 2022 UK GC incident showed that single-level (send time only) fails when the filter has a bug.
- **Single-level enforcement (segment query only)** (rejected). Same issue; a bug in the segment query (missed RGPort call) leaves excluded players in the segment.
- **No Retention agent** (rejected). Engagement use case requires it; the bounds make it safe.
- **Manual review of every Retention agent action** (rejected). Does not scale; agent is meant to draft segments at scale.
- **No negative tests** (rejected). Acceptance criterion; the 4 negative tests are the proof that bounds are enforced.
- **Bonus values set by agent (with approval)** (rejected). Law 18 mandates bonus values set by BonusOffer config; agent involvement (even with approval) creates a loophole.

## Consequences

- 4-level enforcement for Retention agent.
- 4 negative tests (acceptance criterion).
- Retention agent is the most bounded agent (most regulator-sensitive).
- Linter rules 179, 180, 181 enforce the 4 levels.
- Error codes: `E_AGENT_BOUNDARY_VIOLATION`, `E_AGENT_TOOL_FORBIDDEN`, `E_AGENT_CAP_BREACH`.
- The 2022 UK GC incident is the canonical justification; this ADR is regulator-defensible.

## Validation Plan

- **Negative test 1 (excluded player):** Retention agent segment query includes a self-excluded player; assert player filtered out (Level 2); assert journey not queued (Level 3); assert `E_AGENT_BOUNDARY_VIOLATION` if attempted.
- **Negative test 2 (cooling-off player):** same as test 1 but with cooling-off player.
- **Negative test 3 (caps breach):** Retention agent queues journey for player at frequency cap; assert denied by MarketingGate; assert `E_AGENT_CAP_BREACH`.
- **Negative test 4 (bonus value):** Retention agent attempts to call `set_bonus_value`; assert tool not in `allowed_tools`; assert `E_AGENT_TOOL_FORBIDDEN`.
- **Tool registry check (linter rule 179):** grep Retention agent's `allowed_tools`; assert no protection-modifying tools.
- **RGPort check (linter rule 180):** grep Retention agent segment query code; assert calls `RGPort.check_self_excluded` + `RGPort.check_cooling_off`.
- **MarketingGate check (linter rule 181):** grep Retention agent journey queue code; assert goes through MarketingGate.
- **Mid-query self-exclusion test:** player self-excludes mid-segment-query; assert player filtered out (per-player check, not per-segment).
