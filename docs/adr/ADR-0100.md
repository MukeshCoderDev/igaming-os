# ADR-0100 — RNG Port — Production + Deterministic + Certification Adapters

## Context

Random Number Generation is the heart of any game of chance. Regulators in every jurisdiction mandate that the RNG be (a) certified by an approved lab, (b) cryptographically secure in production, and (c) auditable — every RNG output must be reconstructable from a logged seed. Phase 15 (ADR-0095) defined the deterministic sandbox contract; Phase 16 implements the three real adapters that satisfy all three regulator mandates simultaneously.

The three adapters serve three different environments but share a single port interface (`RngPort`):

1. **ProductionRngAdapter** — used in live player-facing rounds. Sources entropy from `secrets.token_bytes()` (CSPRNG backed by the OS kernel's `/dev/urandom` on Linux). Outputs are unpredictable. The seed is logged per round (post-generation) so the round outcome can be audited but not predicted.

2. **DeterministicRngAdapter** — used in sandbox (ADR-0095) and in the certification evidence generator (this ADR). Sources entropy from a `random.Random(seed)` instance seeded from a caller-provided hex string. Same seed → same output sequence. Required for sandbox determinism and for lab-reproducible certification runs.

3. **CertificationRngAdapter** — used during lab certification (Phase 16 ADR-0102). Wraps the DeterministicRngAdapter with additional logging: every call records (seed, call_index, output, round_id) to a tamper-evident log that the lab can verify after the run. The lab gets a deterministic RNG (so they can reproduce the run) plus an audit trail (so they can verify no call was omitted).

## Decision

`RngPort` interface (in `noventra.modules.games.domain.rng_port`):

```python
class RngPort(abc.ABC):
    @abc.abstractmethod
    def generate_seed(self) -> str:
        """Generate a fresh 256-bit hex seed (64 chars)."""

    @abc.abstractmethod
    def next_int(self, *, seed: str, call_index: int, min_value: int, max_value: int) -> int:
        """Return a deterministic int in [min_value, max_value] for (seed, call_index).
        Pre-condition: max_value > min_value; max_value - min_value < 2^32."""

    @abc.abstractmethod
    def next_float(self, *, seed: str, call_index: int) -> float:
        """Return a deterministic float in [0.0, 1.0) for (seed, call_index)."""
```

Key design choices:

- **Seed is a 256-bit hex string.** Large enough that brute-force seed search is infeasible (2^256 search space).
- **`call_index` is explicit.** Each RNG call within a round is numbered (0, 1, 2, …). The (seed, call_index) tuple uniquely identifies an output. This makes audit trivial: a round with N bets has N calls, indexed 0..N-1, each reconstructable from the seed.
- **Same seed + same call_index → same output, regardless of adapter.** This is the determinism property. ProductionRngAdapter uses a fresh random seed per round (logged after generation), but the seed→output mapping is identical to DeterministicRngAdapter given the same seed.

**`ProductionRngAdapter`** implements `generate_seed()` by calling `secrets.token_hex(32)` (256 bits from the OS CSPRNG). The `next_int`/`next_float` methods are identical to `DeterministicRngAdapter` — they derive the output from `(seed, call_index)` using HMAC-SHA256 as a counter-mode PRNG. This means production rounds are unpredictable (seed is random) but auditable (output is reconstructable from the logged seed).

**`DeterministicRngAdapter`** implements `generate_seed()` by returning a caller-provided seed (or a fixed default for sandbox boot). Same `next_int`/`next_float` as Production.

**`CertificationRngAdapter`** wraps `DeterministicRngAdapter` and adds an `audit_log` parameter. Every `next_int`/`next_float` call appends `(seed, call_index, output, round_id)` to the audit log. The log is hash-chained (per Phase 7 pattern) so the lab can verify no call was inserted or removed.

## Alternatives

- **One adapter, env-flagged** (rejected). Hides which RNG is in use; impossible to audit at the code level. Linter cannot enforce.
- **`random.Random` directly** (rejected). Mersenne Twister is not cryptographically secure; predictable from 624 observations.
- **`os.urandom` for next_int** (rejected). Cannot reconstruct from a seed; not auditable.
- **External HSM RNG** (rejected for now). Q5 budget; may add as defense-in-depth later. The CSPRNG-from-OS approach is regulator-acceptable in all our jurisdictions.
- **No call_index** (rejected). Order-dependent; non-reproducible if calls are interleaved across threads.

## Consequences

- Three adapter classes; linter rule 123 enforces that production code paths inject `ProductionRngAdapter`, sandbox paths inject `DeterministicRngAdapter`, and certification paths inject `CertificationRngAdapter`.
- Every round records its `rng_seed_hex` on the round row. The seed is part of the round hash (Phase 16 ADR-0101).
- The `next_int`/`next_float` contract is `(seed, call_index) → output`. Callers MUST number their calls; the adapter does not auto-increment (avoids hidden state).
- A certification run produces a hash-chained log that the lab can verify against the deterministic RNG output. This is the basis for Phase 16 ADR-0102 certification evidence.
- Linter rule 124 forbids direct use of `random.Random`, `random.randint`, `random.random` in the games module — all RNG must go through `RngPort`.

## Validation Plan

- Determinism test: same seed + same call_index → identical output across 1000 calls.
- Cross-adapter equivalence: `ProductionRngAdapter.next_int(seed=X, call_index=0)` == `DeterministicRngAdapter.next_int(seed=X, call_index=0)`.
- CSPRNG test: `ProductionRngAdapter.generate_seed()` returns 256-bit hex; collect 10000 seeds; assert all unique; assert entropy ≥ 7.99 bits/char (chi-square).
- Certification audit log: run a 100-call certification; assert log has 100 entries; assert hash chain verifies; assert no entry can be removed without breaking the chain.
- Linter rule 123: grep for adapter injections; assert production code paths use ProductionRngAdapter.
- Linter rule 124: grep for `random.Random` / `random.randint` in `src/noventra/modules/games/`; assert zero matches.
