# ADR-0098 — RoundVoidingPort Real Adapter + Provider Outage Wallet Protection

## Context

Phase 14 (DEC-0090, ADR-0090) defined the `RoundVoidingPort` interface and shipped a `StubRoundVoidingAdapter` (logs only). Phase 15 implemented a `RealRoundVoidingAdapter` that actually reverses ledger entries when a round is voided by kill switch, self-exclusion, or reality-check failure. But there is a second, related scenario the original port did not address: provider outage.

When a game provider's API times out mid-round — after the player's bet was debited but before the outcome was returned — the player's wallet is locked against a round that may never settle. Without intervention, the funds are stuck until manual reconciliation. For regulated operators, this is a player-protection issue (UK GC RTA §3.4.1) and a money-layer audit issue (the open bet is on the balance sheet as a contingent liability).

The voiding port must therefore serve two callers:
1. **Synchronous callers** (kill switch, SE, reality check) — void immediately, in the same DB transaction as the round state transition. Latency budget: <200ms total (kill switch SLO).
2. **Asynchronous callers** (provider-outage detector) — void after a configurable grace window (default 60s). The grace window exists because the provider may yet deliver the outcome (and the bet should settle, not void).

## Decision

`RealRoundVoidingAdapter.void_round()` performs:
1. `SELECT FOR UPDATE` the round row to serialize concurrent void attempts.
2. `SELECT` all bet rows for the round.
3. For each bet: post a reversal journal entry (Phase 11 `ReversalService`, terminal, references original entry by `source_ref`).
4. Update round state to `VOIDED`, set `voided_at`, set `void_reason`.
5. Emit audit event (Phase 7) + outbox event (Phase 8) in the same transaction.
6. If any step fails, the entire transaction rolls back — no partial voids.

For provider-outage voids, an additional step runs **before** the void:
- A `provider_outage_monitor` Celery task runs every 10s. It queries for rounds in state `OPEN` or `CLOSED` whose `last_provider_heartbeat_at` is older than `PROVIDER_OUTAGE_GRACE_SECONDS` (default 60).
- For each candidate round, the task calls `void_round(reason="provider_outage")`.
- The void is asynchronous (not on the kill switch critical path), so the <200ms SLO does not apply; but the void itself is fast (single transaction).

Provider-outage voids are logged at WARN (not ERROR — outage is an expected failure mode), and an alert fires if the rate exceeds 1% of rounds per hour (configurable).

## Alternatives

- **Manual reconciliation** (rejected). Players wait hours for funds; regulator-reportable.
- **Auto-settle with house-favorable outcome** (rejected). Fraud; misrepresents liability.
- **Auto-settle with player-favorable outcome** (rejected). Bonus abuse vector.
- **No grace window** (rejected). Voids rounds that would have settled normally; provider reputation damage.
- **Grace window >5 min** (rejected). Player-protection violation; funds locked too long.

## Consequences

- `RealRoundVoidingAdapter` is the only voiding implementation; the stub is removed (linter rule 115 forbids `StubRoundVoidingAdapter` in production code paths).
- The provider-outage monitor is a new Celery task with its own schedule. Failure of the task is alertable.
- A new metric `provider_outage_void_count` is exported; alert threshold configurable per tenant.
- The void reversal uses Phase 11 `ReversalService.terminal_reversal()` — same code path as payment refund reversals. Audit trail is consistent.

## Validation Plan

- Void-reversal test: place a bet; void the round; assert ledger reversal entry exists with `source_ref` = original entry.
- Kill-switch void test: trigger kill switch during an OPEN round; assert round = VOIDED + bet returned within 200ms.
- SE void test: activate self-exclusion during an OPEN round; assert round = VOIDED.
- Provider-outage test: simulate no heartbeat for 60s; assert monitor voids the round; assert WARN log + alert fires.
- Concurrent-void test: two callers (kill switch + SE) attempt to void the same round simultaneously; assert exactly one succeeds, the other returns "already voided" without error.
- Linter rule 115: grep for `StubRoundVoidingAdapter` in non-test code; assert zero matches.
