# ADR-0136 — Legal-Hold Matrix & Vendor Registry with Deterministic Expiry

## Context

Legal hold suspends retention/destruction when litigation or investigation is active. Destroying evidence during litigation is itself a crime (obstruction of justice; spoliation). Blueprint §8.3 mandates vendor cert expiry with deterministic rules: lab/studio cert expired → auto-suspend catalog; PSP/KYC/Geo → T-30/7/1 alerts + recorded operator decision.

The 2021 enforcement against a gaming operator (£1.2M fine) illustrated the legal-hold failure: the operator's retention job deleted player records during an active litigation hold because the hold was recorded in a legal department memo but not integrated into the retention job. The deleted records were the evidence the player needed; the court sanctioned the operator for spoliation.

The 2022 enforcement against another operator (£800K fine) illustrated the vendor expiry failure: the operator's KYC vendor's certification expired, but no one noticed for 4 months. The regulator found that KYC checks were performed with an uncertified vendor — a regulator-reportable defect. Blueprint §8.3's deterministic expiry (T-30/7/1 alerts + auto-suspend or operator decision) is the mitigation.

### Legal-hold matrix

Cross-reference of (data_class × jurisdiction × hold_type). **LegalHoldMatrix model:**
- `matrix_uuid` UUID PK
- `data_class` str (e.g., `player_profile`, `ledger_entries`, `kyc_documents`)
- `jurisdiction_code` str
- `hold_type` enum
- `default_retention` str (e.g., `5y`, `10y`)
- `hold_retention` str (e.g., `indefinite` while hold active)
- `notes` TEXT

### Suspension of destruction

- When hold active, retention enforcement job (Phase 9) skips held data.
- Partition drops skip held rows (Phase 7 + Phase 9 pattern).
- **Ledger entries exempt** (AML law — 5-10 year retention mandatory; blueprint §8.1; ledger never destroyed regardless of hold).
- **Linter rule 189:** no destruction of held data (retention job checks legal-hold matrix).

### Release

- When hold released (`status=released`; `released_at` set), retention resumes.
- Held data may be destroyed per normal schedule (after hold release + retention period).

### Deterministic expiry (blueprint §8.3)

**Lab/Studio cert expired → auto-suspend affected catalog items (Phase 16 games; Law 19 linkage):**
- Expiry job sets vendor `status=expired`.
- Auto-suspend: set associated games' `state=suspended` (Phase 16 ADR-0103 release FSM).
- Alert compliance officer + product owner.
- No operator decision required — auto-suspend is mandatory (Law 19; uncertified math cannot be played).

**PSP/KYC/Geo expired → T-30/7/1 alerts + recorded operator decision required to keep running:**
- **T-30:** alert at 30 days before expiry.
- **T-7:** alert at 7 days before expiry.
- **T-1:** alert at 1 day before expiry.
- **On expiry:** alert; operator must record decision (continue with justification OR suspend).
- **Linter rule 190:** no expired PSP/KYC/Geo vendor without operator decision.

### Expiry job

- Scheduled daily (midnight UTC); Celery beat task `check_vendor_expiry`.
- Checks `cert_expiry_date` for all active vendors.
- Sends alerts (T-30, T-7, T-1) — idempotent per vendor per threshold (`last_alert_sent` field).
- On expiry:
  - Lab/Studio: auto-suspend associated catalog items; alert.
  - PSP/KYC/Geo: alert; require operator decision (`operator_decision` field); if no decision within 24h → auto-suspend (conservative default).

### Acceptance criterion: "expiry alert fires"

- T-30 alert test: vendor with expiry 30 days from now → T-30 alert sent.
- T-7 alert test: vendor with expiry 7 days from now → T-7 alert sent.
- T-1 alert test: vendor with expiry 1 day from now → T-1 alert sent.
- Auto-suspend test (lab/studio): lab cert expired → associated games suspended.
- Operator-decision test (PSP/KYC/Geo): PSP expired → alert; no operation without decision; linter rule 190.

## Alternatives

- **No legal hold** (rejected). Regulator-mandated; destruction during litigation = spoliation. The 2021 enforcement is the canonical example.
- **Manual vendor expiry tracking** (rejected). Blueprint §8.3 mandates deterministic rules; manual tracking misses expiries. The 2022 enforcement is the canonical example.
- **No auto-suspend for lab/studio** (rejected). Law 19; uncertified math cannot be played; operator decision cannot override.
- **Auto-suspend for PSP/KYC/Geo** (rejected). Some vendors have grace periods (PSP may continue during transition); operator decision allows informed continuation with documented justification.
- **No operator decision field** (rejected). Regulator asks "why did you continue with expired vendor?"; without recorded decision, operator cannot answer.
- **No T-30/T-7/T-1 escalation** (rejected). Single alert at expiry is too late; operator has no time to transition.
- **Ledger destroyable during hold** (rejected). AML law mandates 5-10 year retention; hold does not override AML.

## Consequences

- LegalHold model + LegalHoldMatrix.
- VendorRegistry model with deterministic expiry.
- Daily expiry job (Celery beat).
- Auto-suspend (lab/studio) + operator decision (PSP/KYC/Geo).
- Linter rule 189: no destruction of held data.
- Linter rule 190: no expired PSP/KYC/Geo without operator decision.
- Ledger exempt from destruction (AML law).
- Open question OQ-COMP-006: vendor expiry T-30/7/1 thresholds (configurable per vendor type; OPEN).

## Validation Plan

- **Legal-hold suspension test:** issue hold; run retention job; assert held data NOT destroyed; assert non-held data destroyed per schedule.
- **Legal-hold release test:** release hold; run retention job; assert previously-held data now destroyed per schedule.
- **Ledger exemption test:** issue hold on ledger entries; run retention job; assert ledger NOT destroyed (AML law mandatory retention).
- **Vendor expiry T-30 alert test:** vendor expiry 30 days out; run expiry job; assert T-30 alert sent; assert `last_alert_sent=T30`.
- **Vendor expiry T-7 alert test:** vendor expiry 7 days out; run job; assert T-7 alert; assert `last_alert_sent=T7`.
- **Vendor expiry T-1 alert test:** vendor expiry 1 day out; run job; assert T-1 alert; assert `last_alert_sent=T1`.
- **Auto-suspend test (lab/studio):** lab cert expired; run job; assert vendor `status=expired`; assert associated games `state=suspended` (Phase 16 ADR-0103).
- **Operator-decision test (PSP/KYC/Geo):** PSP expired; run job; assert alert; assert no operation allowed without `operator_decision`; linter rule 190.
- **Linter rule 189 test:** grep for retention job; assert checks legal-hold matrix before destruction.
- **Linter rule 190 test:** grep for expired PSP/KYC/Geo vendors; assert all have `operator_decision` NOT NULL.
