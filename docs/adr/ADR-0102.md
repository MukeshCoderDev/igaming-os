# ADR-0102 — Certification Evidence — Lab Registry + Auto-Suspend on Expiry

## Context

Every game offered to players in a regulated jurisdiction must be certified by an approved lab. The lab tests the RNG, the math, the game logic, and the RTP. The certification is valid for a period (typically 1–3 years, varying by jurisdiction). After expiry, the game must be withdrawn from production until re-certified.

This is a Legal/Regulatory mandate (Law-REQ-0019, Law 19 in the source blueprint). Failure modes are severe:

- **Operating an expired-cert game** is regulator-reportable in every jurisdiction. UK GC can fine; MGA can suspend the operator's licence. In Ontario, AGCO can revoke.
- **Operating an uncertified game version** (math changed without re-cert) is the same severity.
- **Failing to produce evidence on regulator inquiry** is treated as operating without certification — same severity.

Three subsystems are required:

1. **Lab registry.** A configurable list of approved labs per jurisdiction. GLI is approved in all jurisdictions; BMM in most; iTechLabs in some. The registry is the authority for what counts as "approved lab."

2. **Certification evidence model.** Stores the lab's certification artifacts (RNG cert, math cert, RTP verification, game logic cert). Linked to a specific math version (Phase 16 ADR-0099). Stored via Phase 10 storage port (immutable).

3. **Auto-suspend on expiry.** A daily Celery task scans for cert evidence approaching expiry. On expiry, the game's release status (Phase 16 ADR-0103) transitions to `suspended`. Active rounds are voided (per Phase 15 ADR-0093). New round initiation is refused. Operator is alerted.

## Decision

### Lab registry

`LabRegistry` model:

| Field | Type | Notes |
|---|---|---|
| `lab_uuid` | UUID PK | |
| `lab_name` | str | e.g., "GLI", "BMM Testlabs", "iTechLabs" |
| `lab_code` | str | Short code (e.g., "gli", "bmm") |
| `jurisdictions` | JSONB | List of jurisdiction codes where this lab is approved |
| `is_active` | bool | Soft-delete flag |
| `created_at` | datetime | auto_now_add |

Per-jurisdiction config is Q1-blocked (jurisdiction list is environment-dependent). The registry is configurable via Django admin; changes are audit-logged (Phase 7).

### Certification evidence model

`CertificationEvidence` model:

| Field | Type | Notes |
|---|---|---|
| `evidence_uuid` | UUID PK | |
| `tenant_uuid` | UUID | Tenant scope (RLS) |
| `math_version_uuid` | UUID FK → MathVersion | The math version this evidence certifies |
| `lab_uuid` | UUID FK → LabRegistry | The lab that issued the cert |
| `evidence_type` | enum | rng_cert, math_cert, rtp_verification, game_logic_cert |
| `evidence_storage_uri` | str | URI in Phase 10 storage port (immutable) |
| `evidence_hash` | char(64) | SHA-256 of the stored artifact (tamper-evidence) |
| `issued_at` | datetime | Lab issue date |
| `expires_at` | datetime | Expiry date (1–3 years per jurisdiction; default 2 years) |
| `cert_number` | str | Lab-assigned cert number (e.g., "GLI-23-12345") |
| `created_at` | datetime | auto_now_add |

Evidence is stored via Phase 10 storage port (immutable, retention 7+ years). The `evidence_hash` allows tamper detection: any modification of the stored artifact is detected by recomputing the hash.

### Auto-suspend on expiry

A Celery task `check_cert_expiry` runs daily at 02:00 UTC. For each `CertificationEvidence` row:

1. If `expires_at` is within 30 days → alert (Slack/email to Compliance Lead + Product Owner).
2. If `expires_at` has passed → transition the linked `MathVersion` to status `revoked` (per ADR-0099 synchronous revocation). This cascades:
   - The linked `GameRelease` (Phase 16 ADR-0103) transitions to `suspended`.
   - All active rounds using this math version are voided (per Phase 15 ADR-0093).
   - New round initiation using this math version is refused.
3. The task emits an audit event (Phase 7) and an outbox event (Phase 8).

The 30-day pre-expiry alert gives the operator time to re-certify before the hard suspend. Re-certification flow: new math version → new cert evidence → release FSM transitions to `published`.

## Alternatives

- **Manual expiry tracking** (rejected). Operators forget; regulators fine.
- **No lab registry** (rejected). Cannot distinguish approved labs from unapproved ones.
- **Store evidence in DB** (rejected). Phase 10 storage port is immutable; DB blobs are mutable.
- **No auto-suspend** (rejected). Operating with expired cert is regulator-reportable.
- **Auto-suspend at expiry, no pre-alert** (rejected). Operators get no warning; customer impact is sudden.
- **Pre-alert at 7 days** (rejected). Too late for re-cert (lab turnaround is 4–8 weeks).

## Consequences

- Two new models: `LabRegistry`, `CertificationEvidence`. Migration creates tables + RLS + indices.
- New Celery task `check_cert_expiry` with daily schedule. Failure is alertable.
- Auto-suspend voids active rounds — operator must communicate to affected players (per player-protection regulations).
- Linter rule 128 requires every `MathVersion` in `published` status to have a non-expired `CertificationEvidence` link.
- Linter rule 129 forbids any code path that publishes a math version without cert evidence.
- Linter rule 130 requires the `check_cert_expiry` task to exist and be scheduled.

## Validation Plan

- Lab registry test: create a lab; assert it appears in the approved list for its jurisdictions.
- Evidence storage test: upload a cert PDF via storage port; assert `evidence_hash` matches recomputed hash.
- Evidence tamper test: modify the stored artifact; recompute hash; assert mismatch.
- Pre-expiry alert test: set `expires_at` to 25 days from now; run task; assert alert fires.
- Auto-suspend test: set `expires_at` to past; run task; assert math version → revoked, release → suspended, active rounds → voided.
- Linter rule 128: query for published math versions without non-expired evidence; assert zero.
- Linter rule 129: grep for `status = 'published'` on math version; assert each follows an evidence check.
- Linter rule 130: grep for `check_cert_expiry` Celery task; assert it exists and is scheduled.
